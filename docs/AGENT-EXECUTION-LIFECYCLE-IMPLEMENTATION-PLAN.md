## 1. 已确认目标与边界

Worker 统一裁决业务操作身份、重复执行、完成回执和恢复；Agent、Task State、监督、Desktop 消费同一提交事实。保留现有 Runtime、权限、确认、领域校验、CAS、草稿／正式边界、完整结果存储与本地 SQLite 架构。

Task State 保存目标、要求、进度与监督；Working Data 保存完整资料、产物与历史；ContextManager 只负责每次请求的工作集。正文仍按需检索，聊天附件不自动入库。

不按标题全局去重，不以 provider callId 或内容 hash 作为业务身份。模型声明的输出必须经 Worker 绑定；修改随机 key 不能凭空产生第二份产物。同名独立对象与明确的新输出通过不同持久输出槽位区分。缺少明确身份时返回可处理的冲突／待定位状态，不猜测覆盖或另建。

本地写入、规范回执校验、步骤绑定与提交变更必须在同一事务内成立；传输失败只重发回执。外部任务沿用现有 job 和 unknown/reconcile，不盲目重复付费提交。执行结果必须回传 Agent；大型正文留在 Result Store，必要决策事实保留在回执。

## 2. 模块职责

| 现有基础                                       | 调整                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------- |
| Registry、Provider Loop、Domain Gateway        | 声明执行语义，两条路径接入共同业务执行边界；不改变协议适配层职责              |
| agent_write_receipts、TaskPlan、模型登记交付项 | 复用并扩展为持久操作与输出绑定，记录提交序号、effect、真实 ID／版本及重放关系 |
| AgentContextStore、Task State                  | 保存监督、完整结果、版本化检查点及恢复依据                                    |
| ContextManager、Pi Runtime                     | 根据真实结果推进；区分用户消息与运行时指令；协议整组工作集                    |
| production-skill-validation、checkpoint        | 版本化语义审查与问题闭环；读取和结构检查不冒充语义合格                        |
| 既有任务事件、Desktop 轮询                     | 持久变化序号驱动运行中刷新；终态兜底；保护 dirty 编辑和项目身份               |

逻辑统一不要求引入新的框架、独立事件总线或重写整个 Runtime。
