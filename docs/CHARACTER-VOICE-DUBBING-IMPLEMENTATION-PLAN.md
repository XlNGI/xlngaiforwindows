# 角色固定音色、配音与口型同步实施计划

版本：0.2  
日期：2026-10-14  
状态：首版本地功能与工程验证已完成；真实付费样片及剩余发布验收待完成  
适用范围：Windows Desktop、Worker、Native Provider Bridge、Contracts、Domain、Persistence

> **Agent execution source.** 本计划落实用户选择的“固定角色配音＋口型同步”方案。按 D0–D7 顺序实施；只有阶段门禁实际通过，才能勾选清单并填写验证证据。模型名称、官方参数和接入渠道须在实施时重新核实，不将官网能力视为当前应用已经支持。

## 1. 目标与已经确认的方向

同一个角色在不同场次、镜头的视频中使用固定声音。先确定可试听、可保存的配音，再用视频生成或口型模型匹配画面，最终成片使用已确认的配音文件。

已确认的方向：

- 主路线为固定配音＋口型同步；各段视频不独立随机生成角色声音。
- 角色声音可重复用于不同视频；修改台词可以重新配音，修改画面可以复用原配音。
- 首先验证代表性小样，再决定扩大自动化范围。
- MiniMax H3 可以作为音频参考生成的比较候选；官方参考音频能力不能代替“完整配音被保留”的验证。

2026-10-14 用户授权实施，并明确选择“先完成可运行功能和本地验证，真实付费样片稍后做”。本轮采用 MiniMax Speech 2.8 与 Sync-3 官方协议，先完成 D0–D2 本地能力；D3 的协议与本地夹具验证先执行，真实样片延期，不阻塞 D4–D6 的工程实现。该调整不将真实样片、账号可用性、声音／口型质量或既有发布 HOLD 标记为通过。

首版按条目显式提交付费请求，预算授权只覆盖一次付费尝试；不会自动增加预算重交。成功口型片段按源视频、音频哈希、区间、人物位置、连接和模型的快照复用。用户已有克隆音色 ID 可作为固定音色使用，创建克隆音色和独立角色页试听任务不在本轮实现；角色声音通过场次台词生成和试听验证。

## 2. 首版范围与用户流程

### 2.1 首版建议

| 功能 | 首版行为 |
| --- | --- |
| 角色声音 | 在“角色与场景”的角色资料中绑定一个声音配置，支持试听；先支持供应商固定预设音色，克隆音色作为可选接入 |
| 配音入口 | 在“场次与镜头”的场次页面打开配音面板；场次为编排与完整成片单位，镜头保留为关联、分段和异常修复单位 |
| 台词编辑 | 用户录入或明确导入台词，选择说话角色、顺序、停顿、情绪和位置；台词未经用户确认不自动提交生产 |
| 配音制作 | 按条目生成或导入 WAV/MP3；试听、选择采用的配音版本；时长以音频探测结果为准 |
| 画面处理 | 复用已有场次／镜头视频，或在既有生产面板中按配音时长制作画面；口型处理首版每段只选择一个可见说话者 |
| 成片 | 对指定对白区间处理口型，拼回完整场次，以确认后的配音合成新视频；新视频成功落盘后进入既有素材库 |
| 失败修复 | 分阶段展示错误；可重试失败步骤或替换片段，成功配音和其他成功片段可复用 |

首版包含可编辑的对白条目和视频区间，不建设自由多轨剪辑时间线。多人轮流对白可拆成不重叠的区间逐段处理；多人同时说话先标记为需人工处理，禁止默选人物。

### 2.2 用户流程

```text
角色资料绑定声音 → 试听并保存声音版本
→ 场次录入／导入台词 → 选择角色与情绪 → 生成／导入配音
→ 试听并确认配音版本 → 探测实际时长 → 编排对白区间
→ 选择场次视频／修复镜头视频 → 核对人物、时长与处理费用
→ 处理口型 → 对比试听 → 用确认配音合成完整场次
→ 新成片进入素材库；源视频、配音和任务来源可追溯
```

界面区分“已生成配音”“待试听”“已确认配音”“待处理口型”“待验收成片”；它们是业务进度，不混用异步任务终态。只读项目可查看和播放，不能生成、采用版本、上传或导出新结果。

### 2.3 范围边界

- 首版不自动分离源视频中的对白、音乐和环境声。默认移除源声音轨后加入固定对白，界面在成片前说明原背景声也会移除，并提供试听。
- 环境声、音乐的独立轨道混合、自动压低音乐、复杂时间线、多说话者重叠处理作为后续增强，不作为首版完成门禁。
- 不自动改变配音音高或语速来迁就画面；支持明确停顿、剪分段、重新生成配音或重做画面。
- 不自动克隆声音、不自动切换角色音色、不自动提交整集／全项目批量任务。
- 本里程碑先提供 UI 与 Worker 服务，不扩展 Agent 自动生产、项目检索或普通会话上下文注入。

## 4. 供应商与模型接入策略

首版只接通一条 TTS 路径和一条口型路径。以下是建议验证顺序，不代表用户已选定服务。

| 能力 | 第一候选 | 验证重点 |
| --- | --- | --- |
| 固定音色 TTS | MiniMax `speech-2.8-hd`／`speech-2.8-turbo`＋固定 `voice_id` | 中文、情绪／语速字段、试听、完整音频交付、费用及音色可用性；实际可用模型 ID 在 D0 冻结 |
| 已有视频对口型 | Sync `sync-3` | 本地文件上传、鉴权、人物选择、中文音频、侧脸／遮挡、时长匹配、结果下载与实际费用 |
| 备用口型通道 | 可灵 Lip-Sync | 外部视频、人脸检测、单人选择、格式／大小／时长限制；第一路径未通过时重新做渠道评估，不能静默替换 |
| 音频驱动生成比较 | 万相 2.7 | `driving_audio` 与首帧／首尾帧组合；比较是否更适合从图片直接制作对白镜头 |
| 音频参考生成比较 | MiniMax H3 | `reference_audio` 的音色、台词、节奏遵循度；参考模式与严格首尾帧模式互斥；不作为精确保留配音的已验收路径 |

声音配置锁定供应商连接、账号／地域、模型 ID、模型合同修订、音色 ID、语言与基础语速／音高设置；情绪可以按对白调整，但不能暗中换音色。模型或音色不可用时提示重新选择并创建新版本，禁止回退到“相似声音”。

MiniMax TTS 候选使用 `/v1/t2a_v2` 与 `voice_setting.voice_id`；当前 URL 音频有效期为 24 小时，需要及时落盘；默认 hex 音频需 Native 解码并外置。`speech-2.8-*` 不支持 `whisper` 情绪，表单必须按实际模型开放参数。句／词级时间戳可作为后续连续台词切分的候选，但先验证准确性。

声音克隆不作为首版硬依赖。MiniMax 官方克隆样本为 10 秒～5 分钟、最大 20 MB，需要实名；克隆音色在 7 天内未正式合成调用可能被删除，不能把克隆试听当作长期激活证明。接入时再核对具体渠道的保留期限、激活要求和账号可移植性；预设音色失效与克隆音色失效都必须显式显示，不能删除已保存的配音。

### 4.1 本地文件上传是独立接入门禁

Sync 官方提供本地文件 multipart 提交，以及“申请上传 → 预签名 PUT → 登记资产 → 使用 assetId”的路径。优先验证供应商原生上传，不先建设项目自有公网存储或公开本地服务。

- Rust 通过 Worker 验证后的项目文件句柄／受控临时文件执行流式上传；React 和 Node 不读取 API Key，不自行构造任意主机、路径或请求头。
- `x-api-key`、必要幂等请求头、multipart 和 PUT 分别建立受限合同，不能把现有通用 JSON 白名单扩成任意网络代理。
- 预签名上传地址仅 Native 请求生命周期持有；验证主机、协议和重定向，上传到存储地址时不得附带供应商 API Key。
- SQLite 可以保存非凭据型供应商任务 ID、资产 ID及有效期；签名 URL、上传令牌、鉴权头和音频 Base64 不进入项目库、备份、日志或事件。
- 大 TTS 响应由 Native 外置为临时文件，Worker 复核格式、大小与内容后提交；URL 结果及时下载，过期时按官方查询／刷新协议恢复。
- 官方接口有该能力，不能证明 UniCompAPI 或其他中转已支持；只有选中的具体连接通过上传、提交、查询与下载实测后才启用。

## 5. 数据模型、版本与文件所有权

所有业务记录归属当前项目 SQLite，Worker 为唯一写入者。UUID 为记录标识；时间统一保存 UTC ISO 8601，界面按本地时区显示。下面是待实现的模型草案，D0 冻结字段后再做迁移。

| 对象／建议表 | 关键数据与约束 |
| --- | --- |
| `character_voice_profiles` | `id/project_id/character_document_id/current_version_id/row_version/archived_at`；校验文档为同项目角色；配置改动通过 CAS 指向新版本 |
| `character_voice_profile_versions` | `id/profile_id/project_id/revision/provider_profile_id/model_id/contract_revision/voice_id/settings_json/reference_audio_id/created_at`；生成配置不可变；修改声音创建新版本 |
| `dubbing_cues` | `id/project_id/scene_id/shot_id?/character_document_id?/speaker_kind/text/position/emotion/start_ms?/row_version`；旁白显式绑定声音；对白必须绑定角色；先禁止时间区间重叠 |
| `audio_files` | `id/project_id/kind/relative_path/mime/size_bytes/content_hash/duration_ms/sample_rate/channels/source_job_id?/deleted_at/trash_relative_path`；正式音频不可变，类型包括参考、导入对白、生成对白、场次母带 |
| `dubbing_takes` | 台词 ID／版本、文本哈希、角色声音快照、音频 ID、处理参数、来源任务、试听采用状态；生成新 take 不覆盖旧文件，采用版本通过 CAS 更新 |
| `dubbing_jobs` | 场次／可选镜头、计划版本、幂等键、不可变输入快照、状态、预算快照、采用配音、源视频、最终素材 ID、期限及错误分类 |
| `dubbing_job_steps` | `job_id/step_key/kind/dependencies/status/attempt/provider_task_id/region/input_hash/result_reference/deadline/error`；每次执行保存独立 attempt，已完成结果不可被失败重试覆盖 |

源视频引用应有明确关联记录与外键／同项目约束，并接入既有删除引用检查。当前素材删除检查主要覆盖生产草稿，不能据此认为已保护配音流水线源视频。处于活动任务、待验收或已采用版本中的媒体，在彻底删除前必须检查引用；活动任务输入不得被直接清理。

角色资料改名不改变声音绑定；角色资料删除或归档不级联删除历史配音、任务或成片。来源文档版本、声音配置版本、台词、参数、输入哈希和采用版本写入任务快照；后续编辑只标记“已过期／可重新制作”，不自动付费重做，不改写旧成片。

```text
project.sqlite
assets/audio/reference/{uuid}.wav|mp3
assets/audio/dialogue/{uuid}.wav|mp3
assets/audio/scene/{uuid}.wav
assets/audio/.trash/{uuid}.wav|mp3    # 需恢复的数据，包含于完整项目导出
assets/videos/{uuid}.mp4            # 已完成的新成片
cache/dubbing/{jobId}/{attempt}/    # 可重建中间片段、上传准备与临时结果
```

所有相对路径经项目根解析，拒绝路径穿越、任意绝对路径、符号链接／联接逃逸。文件提交与数据库事务必须有补偿回滚。新增音频仓储具有软删除、恢复与引用保护；既有图片／视频素材库的别名、手动素材组、拖拽快照和成功自动入库规则保持有效。导入格式、文件大小、总时长、台词条数、单条字符数和步骤数量均设服务端硬上限，D0 按选定接口及本地资源预算冻结，不能把供应商无限制或客户端校验作为默认。

迁移验证包括旧 v43 项目顺序升级、重复打开、新库直接创建、跨项目引用拒绝、外键约束、CAS、导出迁移与完整性扫描。实现前按当时 Schema 重新分配迁移版本，并先 checkpoint／备份数据库。

## 6. 时间编排与成片规则

1. 首版按对白条目生成配音，保持角色的固定基础设置；只有供应商明确支持的情绪和上下文参数才能发送。若供应商提供可靠的句级时间戳，可在后续验证同角色连续台词生成后切分；不按文本字数猜切点。
2. `ffprobe` 获得音频实际时长；用户设置条目顺序、停顿和视频起点，以整数毫秒保存。确定配音版本后冻结编排，再准备视频及口型任务。
3. 一段对白允许留白，但不能在未提示的情况下截断尾字。片段过短时拒绝提交，提示减少台词、重做画面或明确重新配音；首版不自动循环、变速或拉伸视频／配音。
4. 视频帧率、时间基和关键帧由 FFmpeg 处理；需要精确对白区间时使用精确裁剪／重编码，不能把 `-c copy` 视为逐帧精确。
5. 处理前选择说话人物；人脸检测失败、角色不明、多人同时说话或片段跨人物切换时拆分／拒绝自动执行。旁白、背影和无可见口型的镜头可直接配音，不支付口型费用。
6. 场次中只对需口型的连续区间处理，其他画面保留。拼回场次后校验时长、区间顺序、帧边界和完整台词，不将原场次切换为默认逐镜头生产。
7. 对口型服务返回的音轨不作为最终配音的权威来源。最终输出使用已确认的本地对白文件；允许格式转换、重采样和明确的音量调整，不自动改变角色音高／语速。
8. 支持源／处理后视频对比试听与成片验收。结果文件完整、可解码且元数据合法，才进入成功终态并原子登记新视频素材；“用户采用”另行更新，不覆盖源视频。

Sync 的时长模式要显式配置：`cut_off` 会截断、`loop`／`bounce` 会循环或倒放、`remap` 会改变速度，均不能作为未经用户选择的补救策略。提交前准备已经匹配时长的片段，并验证供应商输出；Sync 输出会重编码为 H.264，应探测实际帧率、尺寸、色彩与时间基后再拼接，不假设原视频参数保持一致。

场次编排冻结绝对 `start_ms/end_ms`、输出帧率和母带起点。处理后片段先规范化 PTS 起点，再核对实际帧数、结束时间和已知延迟；结构性时间误差首版建议最多一个输出帧，D0 冻结实际容差，口型观感另做人工验收。超限返回失败，不能靠拼接片段实际长度顺延后续对白；最终母带始终按冻结的场次时间放置配音，禁止使用最短流截断把尾字或后续片段丢掉。

## 8. 状态机、幂等与恢复

配音计划从 `draft → prepared → submitted`；提交后的输入与预算快照不可变。台词或声音变化创建新的计划版本。

```text
步骤：pending → running → complete
                       → failed
                       → cancelling → cancelled
                       → interrupted → recovered / failed

远端步骤内部：uploading → submitting → polling → downloading → validating
本地步骤内部：processing → validating → committing
业务验收：待试听／待验收 → 采用／不采用（独立于任务终态）
```

`recovered` 表示恢复事件，不是永久状态；本地步骤恢复到可执行状态，已有远端任务 ID 的步骤恢复到查询／下载状态，最终必须进入 complete、failed 或 cancelled。

- 远端请求开始前持久化 attempt、输入哈希及幂等键；收到任务 ID 后立刻保存供应商、连接与地域，再启动查询。
- Sync JSON／multipart 提交复用首次持久化的 `Idempotency-Key`；按官方当前的 7 天保护期及活动／未知任务延展规则核对恢复窗口。不能为了重试未知提交创建新 key；输入改变则建立明确的新任务。
- 提交超时且结果不明时，标记 `submission_unknown`；优先按供应商幂等／查询协议核对。没有可核对接口时要求用户处理，不自动再次提交计费任务。
- 重启可继续查询已经登记的远端任务；只重做可安全复现的本地分段／合成，不重新生成成功配音。
- 不支持远端任务查询的同步 TTS 请求中断后，不可把缺失音频当成功，也不可自动再扣费；保留明确的重新生成入口。
- 取消先写本地状态并停止后续步骤；远端取消按官方能力尽力执行，失败不恢复本地任务，也不承诺退费。
- 关闭／切换项目停止本地进程与调度；旧回包不能写新会话。重开原项目时按原任务 ID 和有效期恢复，取消任务不会重新启动。
- 同项目多个任务有有界队列、并发与轮询退避；首版默认一个本地 FFmpeg 任务，远端并发遵循选定连接限额。
- 试听 TTS、声音克隆、正式配音、口型和重试全部计入已选定预算；界面区分首轮与重试费用，并保存最大尝试次数。按估价预留额度，缺价格、预计超额或达到次数上限时暂停自动付费步骤，只能由用户明确单次继续或调整预算范围。
- 提交结果不明的步骤仍占预算风险额度，不能当作未计费请求释放后再次自动提交。预算是本地估价与调度约束，不能保证供应商实际扣费不变；记录估算与实际用量差异。完整台词和请求正文不写诊断日志。
