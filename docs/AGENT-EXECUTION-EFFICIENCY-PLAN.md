# Agent 执行编排与往返优化

日期：2026-11-08。用户批准实施。沿用项目检索规则与统一 Runtime、ContextManager、Task State、Result Store、业务执行边界，不新增平行执行系统。原始要求、正式产物、权限、CAS、幂等、真实工具回传和语义审查均保留。

## 基线与根因

2026-11-07 隔离六镜／60秒任务：74次有usage的请求、2次中断；净观察1267秒。按responseId去重为73次单工具回复与1次最终答复。完整输入合计4,349,837 Token。文档6份实际提交13次；资料搜索／读取18次，制作读取14次。业务失败和执行前失败存在重叠，不相加。首次失败与20分钟观察超时继续保留。

已复核：Rust对所有工具统一设置parallel_tool_calls=false，而Worker已有parallel-readonly与批处理；resourceMap.revision和structure.revision含义不同；失败提交依赖模型重发完整参数；普通schema/ID错误也缩小镜头批次；已知产物读回仍依赖逐项搜索。

## 实施顺序

1. [x] E1 统一调度：Registry声明执行语义传到协议层，允许模型提出多个读取；执行层在任何写入前拒绝混合／多写批次，仍逐调用授权、校验、回传。两协议验证。
2. [x] E2 句柄与内容复用：复用完整Result Store持久化待提交参数，为失败返回可引用的prepared结果；同任务／同工具引用校验及合并后重新校验，保持权限和CAS。提供清晰的目录版本、计划槽引用，避免复制UUID；禁止按标题猜测或自动刷新真实冲突版本。
3. [x] E3 批量按需读回：由已知产物／审查目标生成可直接执行的版本化读取引用，模型显式发起批量读取；完整分页／读取回执／增量审查沿用既有机制，不自动注入正文。修复分批恢复分类，仅体积／截断问题缩小批次。
4. [x] E4 ContextManager精简每轮任务投影与重复元信息，保留持久原文和待办入口；失效版本退出工作集，真实成功／失败继续返回Agent。
5. [x] E5 全仓门禁与真实业务对比：相同任务、相同模型／协议、隔离项目，保留强杀恢复和独立内容审查；分别统计请求、重复读取、失败、usage和耗时，不设调用次数硬上限冒充效率。真实结果不满足目标时按证据报告／修复。

每阶段实施后记录实际测试；仅完成后勾选。旧接口兼容、无历史删除；必要新增协议字段采用可选形式，不破坏旧项目。安装或替换用户运行实例不在本轮范围。

## 验证重点

- 多读成功、混合读写／多写零写入、每调用独立授权及真实结果。
- prepared正文跨失败和重启可复用；跨任务／错工具／损坏hash／未知字段被拒绝；原正文不变。
- 句柄不覆盖用户编辑；真正CAS冲突须回传决策；幂等重放不重复保存。
- 读回按需、draft/published标记、范围／版本校验；批量部分失败如实回传，读回不等于语义通过。
- schema/ID错误不缩批，截断／过大才缩批；原资料、检查点、正式产物不丢。
- 模型能力／上下文窗口不因本轮优化改大；计数区分模型请求、工具调用和持久结果。
