日期：2026-10-16。执行顺序：审计 → 合同 → 本地执行 → 模型适配与表单 → 连续性与回归。

## 已确认的业务要求

- 用户在角色与场景准备图片和声音，在场次与镜头调整关系；进入制作表单后亲自选择供应商和模型。
- Agent 返回结构化执行清单，系统执行已授权的本地操作。清单不自动提交付费媒体任务。
- 提示词结构覆盖人物外观、环境、画面、动作节拍、镜头、对白、声音、生成参数、素材需求、连续性状态及约束；字段按实际任务填写。
- 提示词自动扩写 `promptExtend` 是可选的模型设置：只向声明 `prompt_extend` 的模型传入，其他模型使用原提示词且不因此阻止制作。保存的偏好保留，切回支持模型时继续生效；其他制作能力冲突仍按原规则校验。
- 通用输出设置是制作偏好，不是所有接口的必填参数。按所选 Schema 投影；不支持或不在模型范围内的普通设置给出适配说明，由当前模型表单提供可选值。未指定声音时使用 auto，沿用模型默认；只有明确选用音色、录音或必需素材才要求对应输入。详细规则及验证见 [业务与 Schema 对接修复](./PRODUCTION-SCHEMA-BINDING-IMPLEMENTATION-PLAN.md)。
- 页面和执行模块读取同一项目 SQLite。手动修改增加业务版本，不改变官方模型合同。
- 运行状态由系统维护；LLM 不得伪造素材 ID、成功状态、模型能力或任务结果。
- 保存文档草稿、场次结构审核、付费确认、按需检索及素材默认/指定/不使用规则继续沿用既有入口。
- 不保证生成模型严格遵守剧情；连续性检查只对显式结构化事实作确定性判断。

## 使用及边界

1. Agent 按需读取项目目录及对象版本，使用原有工具创建角色/场景草稿、提交场次关系审核。新实体尚未批准时，不能给它编造 ID 执行制作指令。
2. 对已有真实对象调用 `production.read` 后，以 `production.execute` 提交清单。当前清单的本地操作为 `set_prompt`；关系审核、素材制作、付费任务继续使用现有入口，不增加一套绕过审核的关系写入器。
3. 用户进入制作页选择模型，本地编译结构化内容并预填参数。普通输出偏好不适用时显示适配说明；明确要求的声音输入不受支持、素材缺失、剧情超长等显示阻塞冲突。没有独立负向字段时将约束保留在主提示词；不自动提交。
4. 改图片/声音选择后，可重新填入以同步当前素材。修改剧情文本或角色关系后，需要 Agent 基于当前内容保存新指令版本；重新读取不能自行猜测新剧情。
5. 清单最多 30 个操作、512 KiB；连续性最多检查 200 个依赖对象。复杂度应服务于表达需求，不要求把无关字段填满。

声音与引用适配按仓库中已登记的具体合同修订执行。通用 Schema 能校验字段，不能证明语义或真实生成效果；未登记的供应商能力返回明确冲突，不宣称覆盖市场上全部接口。生成视频的角色外观、对白还原及剧情连贯性仍需用户验收。

## P6 完整场次与逐镜头制作（2026-10-17）

### 已确认要求与不变量

- 场次按剧情逻辑、人物目标和情节转折组织；分镜服务于叙事。先创作，再根据台词、动作、停顿和运镜估算时长，禁止为凑满 15 秒或模型上限添加无意义镜头、拉伸动作或删改剧情。
- 结构区分故事时间（年代、季节、日夜时段）、分镜预计时长、模型请求时长和素材实际时长。镜头内节拍使用镜头相对时间，整场时间轴由有序分镜推导。
- 新制作结构包含叙事目的、时间地点、细分视觉风格、人物状态、构图运镜、对白声音、参考素材与连续性；旧版文本和 v1 指令继续可用。
- 生成结构仍经原变更集审核；批准前不写入实际场次/分镜。结构与文本在同一项目 SQLite 原子保存，真实 ID、CAS、版本、审核边界不变。
- 场次制作表单读取共享设定与全部分镜，按顺序显示完整内容，并根据用户所选模型自动填写时长、比例、分辨率、声音和参考输入。模型限制不能反向决定剧情编排。
- 分镜增删、修改、排序、风格或参考变更必须影响制作来源令牌；历史任务保留原快照。人工表单覆盖继续保留。
- 超出单次模型能力时保留完整场次和可检查的自然镜头分段建议，不能静默截断、改写或自动提交多个付费任务。
- 普通会话不新增正文自动注入；项目和素材仍本地优先。

### 所有权、状态与故障处理

结构归当前项目的实际场次/分镜，待审核结构归变更集；批准复用 proposed → applied/conflicted/rejected 状态机。制作编译为本地只读操作，不新增后台状态机。切换项目/模型或异步迟到结果沿用现有上下文隔离；批准失败整批回滚；重复批准不重复创建；提交前来源变化阻止使用旧快照；模型不支持、缺失时间、时长冲突、提示词过长均可见，完整提示词仍可检查。

## 角色设定板与视频参考图要求（2026-10-18 确认）

用户明确采用含多视角和局部细节的角色设定板作为视频角色参考。示例图一、三、四认可的是此类信息组织形式；单幅树下坐姿剧情画面（示例图二）不符合本次角色素材交付要求。示例认可不代表其中每张已经包含完整三视图，也不代表三种不同画风可以混用。

- 完整角色设定板至少包含正面、侧面、背面全身三视图，完整展示头顶至鞋底；三视图人物身份、比例、发型、服装与配饰保持一致。表情差分或不同动作不能替代三视图。
- 同板提供正侧面头部、发型、服装结构与纹样、关键配饰、鞋履、标志道具及辨识特征的局部细节。表情差分和材质色卡可作为补充；分区清楚且细节可辨。
- 全体角色继承同一项目美术标准。统一绘制方式、写实程度、人体比例体系、线条、上色、材质与光影，不以排版相似代替画风一致。
- 视频生成实际使用用户确认的完整角色设定板，并说明各区域对应同一人物的不同视角和细节。文字、边框、面板和多视图排布不作为视频画面要求。
- 角色设定板作为外观参考，首帧作为镜头构图输入，按模型能力区分参数用途。不得静默裁减或替换用户选择的设定板；只有首帧能力的模型需说明限制，按分镜另行准备首帧。
- 图片请求成功不等于角色素材验收通过。最低内容缺项、跨视图身份变化和跨角色画风漂移均属于待修正问题。

本次将上述约定写入内置会话模板，供新会话或用户主动重新载入时编辑使用；已保存会话模板和项目素材保持用户管理。实际生图提示词编译、设定板内容检查、验收状态及所有生成入口的统一约束尚未在本次模板更新中实现，不计为 P6 新增工程能力完成。
