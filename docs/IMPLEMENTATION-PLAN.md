# 实施计划

版本：0.7  
日期：2026-08-01

当前基线：M0–M4 已完成本轮高风险修复、自动化复验、Release 同目录启动冒烟和 GitHub Windows runner 干净 NSIS 安装生命周期验证，M5 尚未开始。项目锁竞争、损坏恢复连接、LLM/Sidecar 超时、stderr 排空、中文 token 预算、原生凭据桥、完整 adapter key、流增量批量持久化和桌面异步竞态已有回归测试。最终发布签收保持 `HOLD`，等待真实 OpenAI 和真实 Vidu 成功请求；这些验证不得由 Mock 结果替代。

## 1. 实施原则

- 先完成可迁移、可备份的内置 SQLite 数据层，再实现 LLM 和模型调用。
- 先打通一个完整镜头闭环，再增加更多厂商和能力。
- UI、Worker 和适配器共享 TypeScript 类型与 JSON Schema。
- 所有外部响应均视为不可信输入，必须校验和规范化。
- 每个里程碑都必须具备自动测试和可人工验证的演示路径。

## 2. 里程碑顺序

```text
M0 工程骨架
-> M1 SQLite 项目数据层
-> M2 项目文档与会话
-> M3 上下文和 LLM
-> M4 适配器与动态参数 UI
-> M5 生图闭环
-> M6 生视频与本地轮询
-> M7 稳定性和发布
```

### 2.1 阶段总览与门禁

| 阶段 | 目标 | 阶段结束时的可演示产物 | 进入下一阶段的门禁 |
|---|---|---|---|
| P0 方案冻结 | 固化产品边界和架构 | 启动文档、实施计划、API 能力清单 | 核心职责和 MVP 范围无歧义 |
| M0 工程骨架 | 验证桌面技术链 | 四栏空工作台、Worker 健康检查、SQLite 测试库 | 干净 Windows 环境可安装运行 |
| M1 项目数据层 | 建立可靠本地项目 | 可创建、打开、备份、迁移项目 | 崩溃、迁移、恢复和单写实例测试通过 |
| M2 文档与会话 | 建立创作资料库 | 大纲、计划、角色、场景、镜头和独立 Chat | 正式文档与普通对话边界正确 |
| M3 LLM 上下文 | 建立导演会话闭环 | LLM 基于当前场次/镜头生成可复制产物 | 来源可见、约束生效、上下文不串场 |
| M4 适配器 UI | 建立生产配置能力 | 选择方式/厂商/模型后动态显示表单 | Schema、业务规则和凭据安全通过 |
| M5 生图闭环 | 验证第一条真实生产链 | 提示词复制、同步生图、资产归档 | 失败不留脏数据，结果可关联镜头 |
| M6 生视频闭环 | 完成异步任务链 | 首尾帧视频提交、轮询、重启恢复 | 多任务、限流、失败和取消可恢复 |
| M7 发布稳定化 | 形成可交付产品 | 签名安装包、诊断、备份恢复、示例项目 | 完整端到端和升级测试通过 |

任何阶段门禁未通过时，不提前开发依赖它的正式业务功能。允许制作技术原型，但原型不能直接并入主流程。

## 3. M0：工程骨架

阶段目标：证明 Tauri、React、Node sidecar 和内置 SQLite 能作为一个无需额外运行时的 Windows 安装包交付。

任务：

- 创建 pnpm workspace。
- 创建 Tauri 2 + React + TypeScript + Vite 应用。
- 创建 Node.js/TypeScript Worker 和共享 packages。
- 建立 Tauri 与 Worker 的 IPC 协议。
- 集成 SQLite 驱动并验证 Windows x64 原生模块打包。
- 配置 ESLint、Prettier、TypeScript、Vitest 和基础 CI。
- 验证 Windows 安装包可以携带、启动、停止和重启 Worker。

验收：

- 桌面应用可以启动并显示四栏空工作台。
- UI 可以调用 Worker 的 `health` 方法并接收版本信息。
- 安装包可以在没有 Node.js 和数据库软件的干净 Windows 环境中创建、读写 SQLite 测试库。
- 关闭应用后不残留 Worker 进程。

阶段产物：

- 可安装的内部开发包。
- IPC 协议 v1 和错误返回规范。
- SQLite 原生模块打包验证记录。
- 四栏工作台基础布局。

## 4. M1：SQLite 项目数据层

阶段目标：在接入任何 LLM 和生成 API 前，先建立可迁移、可备份、可恢复的本地项目容器。

任务：

- 定义 `project.sqlite`、初始 Schema 和 `schema_version`。
- 实现新建、打开、关闭和最近项目。
- 实现 Project、Document、Conversation、Memory、Constraint、Asset、Job Repository。
- 开启 WAL、外键约束和 busy timeout，明确 Node Worker 为唯一写入者。
- 实现事务、迁移、checkpoint、SQLite backup API 和完整性检查。
- 实现第二实例只读打开和异常退出恢复。
- 实现路径边界检查和项目目录导入导出。
- 建立 `assets/`、`cache/`、`exports/` 和 `backups/` 目录规则。

验收：

- 强制终止应用不会产生半完成的文档版本或任务状态。
- 两个实例打开同一项目时只有一个实例可写。
- 通过应用导出的项目包可以在新位置打开。
- 旧 `schema_version` 测试项目可以自动迁移。
- 数据库完整性检查、备份和恢复测试全部通过。

阶段产物：

- 数据库 Schema v1 和迁移工具。
- 项目新建、打开、只读、备份、恢复和导出流程。
- Repository 接口及事务边界文档。
- 媒体目录和资产路径规范。

## 5. M2：项目文档与会话

阶段目标：用户不接入任何模型 API，也能完整建立和维护短剧项目资料。

任务：

- 实现大纲、项目计划、角色、场景、分镜文档编辑器。
- 实现文档版本列表、当前版本和恢复旧版本。
- 实现项目、场次、镜头三级会话作用域。
- 实现 Chat 消息分页存储、流式写入完成标记和复制按钮。
- 实现“保存为项目文档”“添加到项目记忆”“添加生产约束”。
- 实现项目树、镜头列表和右侧独立会话栏。

验收：

- 未保存的普通对话不会修改正式文档。
- 保存会话产物会创建新版本，旧版本仍可查看。
- 切换镜头后会话作用域和当前引用标识正确更新。
- 文档版本和当前版本指针在同一事务内更新。

阶段产物：

- 可版本化的大纲、计划、角色、场景和分镜编辑器。
- 项目、场次、镜头三级会话。
- 会话产物的复制和显式保存入口。
- 项目树、镜头列表和独立 Chat 列。

## 6. M3：上下文和 LLM

阶段目标：让 LLM 稳定地按照正式大纲、计划、记忆和当前镜头工作，但不替用户填写生产参数。

任务：

- 定义 `ProductionContext` 和来源引用格式。
- 实现按项目、场次、镜头加载相关文档。
- 实现项目记忆、生产约束和最近对话合并规则。
- 实现上下文长度预算、长文档分段和摘要缓存。
- 实现 LLM Provider 接口和首个 LLM 供应商。
- 实现流式会话、停止生成、重试和错误恢复。
- 在会话顶部显示本次使用的文档和版本。

验收：

- 当前镜头回答不会引用无关场次内容。
- 锁定约束始终进入上下文。
- 用户可以查看回答所依据的文档版本。
- 更换 LLM 不改变项目文件格式。

阶段产物：

- `ProductionContext` v1。
- 上下文来源和版本查看器。
- 首个 LLM Provider 适配器。
- 可复制的角色、场景、分镜和提示词内容块。

## 7. M4：适配器与动态参数 UI

阶段目标：用户的“生产方式 + 供应商 + 模型”选择可以唯一转换为 API 端点、字段 Schema 和校验规则。

任务：

- 定义 Capability、AdapterDescriptor、JSON Schema 和 UI Schema。
- 实现 Adapter Registry 和唯一解析规则。
- 实现字段控件映射、表单校验和专业参数折叠区。
- 实现供应商凭据配置和 Windows 安全存储。
- 实现参数草稿的 SQLite 持久化，但不允许 LLM 自动填写。
- 实现模型能力、素材数量、时长和分辨率的组合校验。

验收：

- 选择生产方式、供应商和模型后能唯一锁定适配器。
- 切换适配器后只显示官方支持的参数。
- 无效字段组合不能提交。
- API Key 不出现在项目文件和日志中。

阶段产物：

- Capability Registry 和 Adapter Registry。
- 动态表单渲染器与参数草稿。
- 凭据配置页。
- 模型能力矩阵和适配器契约测试框架。

## 8. M5：生图闭环

阶段目标：打通第一个真实模型生产闭环，用最小接口验证提示词、参数、资产和错误处理的整体设计。

首批接口：

- Vidu Image2 同步文生图和图片编辑。
- Vidu/Gemini 协议参考生图。

任务：

- 实现同步请求、超时、取消和错误规范化。
- 实现 URL/Base64 输入检查和结果落盘。
- 实现图片资产 manifest、缩略图和来源追踪。
- 实现结果保存、删除、重命名和关联镜头。
- 为适配器增加契约测试和固定响应样本。

验收：

- 用户可从 Chat 复制提示词并完成一次生图。
- 结果可以保存为角色、场景、首帧或尾帧资产。
- 请求失败不会生成残缺资产记录。

阶段产物：

- 至少一个可发布的同步生图适配器。
- 图片素材库、缩略图和镜头关联。
- 脱敏请求快照和厂商错误映射。

## 9. M6：生视频与本地轮询

阶段目标：在没有公网回调服务的条件下，可靠完成异步视频任务和重启恢复。

首批接口：

- Vidu 文生视频。
- Vidu 图生视频。
- Vidu 参考生视频。
- Vidu 首尾帧生视频。

任务：

- 实现异步任务提交和 `providerTaskId` 事务化持久化。
- 实现带退避和随机抖动的轮询调度器。
- 实现应用启动后的未完成任务恢复。
- 实现暂停轮询、继续查询和厂商支持时的取消任务。
- 实现结果 URL 校验、下载、资产登记和本地通知。
- 实现任务列表、状态、错误、耗时和成本展示。

验收：

- 应用重启后可以恢复查询进行中的视频任务。
- 多任务轮询遵守厂商限流且不会重复启动。
- 成功、失败、超时和取消状态都能稳定写入 SQLite。
- 未设置公网 `callback_url` 时完整流程仍可运行。

阶段产物：

- 文生视频、图生视频、参考生视频和首尾帧生视频适配器。
- 本地轮询调度器和任务状态机。
- 应用重启恢复、取消和结果下载能力。
- 任务中心和本地完成通知。

## 10. M7：稳定性和发布

阶段目标：将技术闭环转化为普通用户可以安装、迁移项目和自行排障的 Windows 产品。

任务：

- 增加日志脱敏、崩溃报告导出和诊断包。
- 增加 SQLite 一致性备份、项目恢复和媒体缓存清理。
- 增加离线启动、网络切换和系统休眠恢复测试。
- 增加大文件、低磁盘空间和损坏 JSON 测试。
- 完成 Windows 安装、卸载、升级和签名流程。
- 完成首次启动、API 配置和示例项目体验。

验收：

- 核心路径具备端到端测试。
- 用户可导出脱敏诊断信息。
- 升级应用不会改变或损坏已有项目。
- 发布构建不依赖用户预装 Node.js。

阶段产物：

- Windows 签名安装包和升级包。
- 项目备份/恢复工具。
- 脱敏诊断包和用户错误指引。
- 示例项目、首次启动流程和发布检查清单。

## 12. MVP 切分建议

首个可用版本只需要：

1. 一个 LLM 供应商。
2. Vidu Image2 或参考生图中的一个同步生图适配器。
3. Vidu 首尾帧生视频一个异步适配器。
4. 项目大纲、项目计划、角色、场景和镜头文档。
5. 项目/镜头会话、复制提示词和手动填写参数。
6. 本地资产、任务轮询和重启恢复。

参考生视频、多 LLM、更多生图模型和专业参数可以在首个闭环通过后增加。

## 13. 每阶段内部实施顺序

每个阶段统一按以下顺序执行，避免 UI、数据和业务规则彼此脱节：

```text
1. 固化用例和输入/输出
2. 定义领域类型、数据库变更或 Schema
3. 实现 Repository / Service / Adapter
4. 实现 IPC 合同
5. 实现 UI 和错误状态
6. 完成单元、契约和集成测试
7. 执行人工演示与阶段门禁
8. 更新架构、迁移和用户文档
```

数据库变更必须先提交迁移和回滚/恢复测试，再由业务代码使用。厂商 API 变更必须先更新能力矩阵和契约样本，再修改动态表单。

## 14. 启动前默认配置

若没有新的产品决策，工程启动时采用以下默认值：

- 仅支持 Windows 10/11 x64。
- 单个项目同一时间只允许一个可写实例。
- 项目目录由用户选择，包含 `project.sqlite` 和媒体目录，不放在应用安装目录。
- 媒体默认下载到项目 `assets/`，同时保留来源 URL 和请求快照。
- 参数草稿按镜头和适配器保存。
- LLM 产物只在用户显式操作后进入正式项目文档。
- 视频任务仅本地轮询，应用关闭后不承诺实时通知。

## 15. 完成定义

每个功能只有同时满足以下条件才算完成：

- 有明确领域类型、数据库 Schema 和媒体目录格式。
- 有输入校验和用户可理解的错误信息。
- 有单元或契约测试。
- 应用重启后状态可恢复。
- 日志不泄露凭据和大段 Base64。
- UI 在常见笔记本宽度下无重叠和不可达控件。
- 相关架构和用户文档已同步更新。
