# 单 Agent 连续创作设计计划

日期：2026-10-21。依据本会话的只读审计及用户确认。状态：设计已确定，实施进度见[实施计划](./AGENT-SEQUENTIAL-AUTHORING-IMPLEMENTATION-PLAN.md)。

## 1. 目标与范围

让同一制作任务由统一 Agent 顺序完成：读取依据、编排、逐场生成、保存、按实际产物续写、整体复核。沿用 `ProductionInstruction v2`，统一核心语义，分开场次共享内容、镜头内容和 Worker 保存协议。实现类型为 `ProductionSceneAuthoringIR`、`ProductionShotAuthoringIR` 和 Worker 保存回执；表单仍读取本地合成后的 instruction/text。

本次保留已有多会话任务调度、全局文本容量 4、同项目容量 2、只读工具并行、小说批任务及媒体调度。不新增场次/文档的多 Agent 自动分工，不创建新的并发生成池。

## 2. 审计依据

2026-10-21 最近一次任务先后发生整包 JSON 语法错误、分段字段层级错误、可选日期空字符串及省略版本号后误报版本冲突，最终耗尽修复次数。原始失败 JSON 未保留，无法确定语法错误源于模型还是传输。

分段清单包含 17 场、47 镜；旧接口完成至少需要 36 次调用，超过单任务 32 次上限，且全部 finalize 才显示场镜。工具声明只要求 operation/resourceId，执行却另有隐藏必填条件。项目资源说明仍提及 videoPrompt，与 instruction-only 契约不一致。

## 3. 已确认规则

1. 创作语义由 Agent 判断；Worker 不按姓名、标题或关键词推断角色、场景、前置剧情和任务目标。
2. 本地 SQLite 是计划进度、对象关系和产物的权威。GitHub 只管理源码与审阅。
3. 资料正文、记忆和约束按需检索；保留 draft/published 标签；未导入或保存的附件不入索引。
4. 角色/场景资料用于确认事实和选择参考，不整段拼进视频提示词。只绑定本镜出场或原文明示的画外角色。
5. 草稿保存无需再次批准；未确定事实作非阻断提醒，不编造日期、人物、对白或前置状态。
6. 用户最终制作表单优先，IR 用于来源和辅助编译，不覆盖手工输入，不恢复剧情证据类提交阻断。
7. ID、权限、项目边界、CAS、循环、容量及模型真实接口参数仍严格校验。结构错误不降级为执行成功。
8. 旧文本、v1/v2 IR、既有分段及历史任务继续可读；用户现有内容不批量重写。

## 4. IR 分层

| 层 | 所有权与内容 |
| --- | --- |
| 共同语义 | 沿用 ProductionInstruction，复用人物、节拍、对白、声音、事实和引用定义 |
| 场次 IR | 时间、地点、环境、共享风格/灯光、参考人物的稳定属性 |
| 镜头 IR | 本镜名单、站位、视线、动作、对白、起止状态、定格、相对时间、摄影 |
| 本地合成 | 在现有继承函数中形成有效镜头；只为实际声明人物补充共享属性，不继承其他镜头动作或人物 |
| 保存协议 | stageId、操作、版本、幂等与预算由 Worker 校验；不写进创作 IR 或系统提示词 |
| 模型适配 | 沿用本地 compiler；各模型共用创作语义，不增加 LLM 格式转换轮次 |

场次共享人物的服装、外观等可被本镜明确值覆盖；站位、表情、动作、初始/结束状态不从场次人物描述自动带入每镜。镜头摄影采用本镜明确要求；场次的单次运镜、起止画面不自动重复到每镜。程序不能仅靠字符串判断衣色、残肢和叙事矛盾，语义疑点仍由 Agent 复核。

可选描述字符串为空或纯空白时，在模型创作入口规范化为省略；必填正文、ID、未知字段、显式数组和错误类型不借此放宽。手工表单不走这条规范化路径。

## 5. 工具与版本

分段工具保留稳定名称和有界 Schema，按操作声明必填字段。begin、get、put_scene、put_shots、finalize 与 checkpoint 的合法形态和 Worker 保持一致。

版本号允许显式提供；省略时，仅使用本任务最近一次成功工具结果中实际观察到的该 stage 版本。没有可信观察则要求先 get；观察已过期则报真实冲突。不得直接取数据库最新版本代替调用者基线，也不得覆盖用户修改。

错误区分参数缺失、字段路径、版本冲突、参考缺失和预算中断；保留既有有界 JSON/Schema 修复与请求上限。未知语法错误不猜测或执行残缺参数。

## 6. 计划、保存与续作

复用 scene_structure_stages：begin 落盘场次顺序和镜头数量；每个场次包含共享内容、已暂存镜头、实际保存的 changeSetId/sceneId/shotIds，以及绑定资料的版本元数据。元数据记录的是实际版本观察，不把草稿标成正式，不声称模型读取了未读取的正文。

1. 先读取资料，保存经语义编排的有序清单；用索引定位清单项，用真实 ID 定位实际产物。
2. 顺序保存一场共享内容和少量镜头。最后一批镜头到齐后，在同一事务中保存该场及其镜头，立即进入现有页面。
3. 每场独立原子提交。后续场次失败不撤销先前完整场次；同一场失败不产生半套父子关系。
4. 完整场次保存后冻结该清单项；修改已保存对象走原 ID/CAS 更新入口，不通过重新提交分段创建副本。
5. get 返回有界进度、真实 ID、未完成索引、资料版本变化提示和下一步定位；正文仍通过原工具按需读取。
6. 接续剧情只引用真实前序场次/镜头；人物/场景资料不是 predecessors。未建立的前置状态保留待核实。
7. 每次任务保留既有 24 请求和 32 业务调用上限。长计划分多个有界执行轮次续写，不自动启动额外 Agent 或绕过额度。
8. 任务在额度前可显式 checkpoint：保留已写进度并标为部分完成、可继续。没有写入实质内容的空清单不能冒充进度；普通失败不自动改称 checkpoint。
9. finalize 对完整清单幂等确认；未完成清单不能返回整体完成。

文档继续使用原草稿入口及真实 documentId/versionId。先保存依据资料，再生成使用它的场镜；多份文档顺序提交。整体复核由同一 Agent 按需读取已保存结果完成，程序检查真实引用、重复与范围，语义连贯性不冒充确定性保证。

## 7. 状态与所有权

| 对象 | 状态/位置 |
| --- | --- |
| 清单 | 项目 SQLite；待写 → 部分暂存/部分场次已保存 → 全部保存 |
| 场次项 | 待写 → 暂存 → 原子保存；已保存项不可从 staging 改写 |
| 模型任务 | 原 running → completed/failed/cancelled；显式 checkpoint 的回复可结束，但 outcome=partial，不能标为全部交付完成 |
| 来源 | 项目/会话范围内的真实文档与版本元数据；改变时提示重新核对 |
| 请求 | 原 generation/attempt/request 账本；所有实际请求继续独立记用量 |

清单归 project/conversation，执行权限归当前 task/generation/session。跨会话、跨项目、旧会话身份及取消后的迟到结果不得写入。

## 8. 缓存与观测

- 保留懒加载、稳定工具顺序和任务内有界集合；分层不要求每镜切换 Schema。
- 原系统提示、冻结上下文及用户输入保持不变。恢复反馈追加为 user/tool 轮次；不把动态错误、资料版本或进度拼回 system。
- 补充消息及预算整理继续遵循既有协议；仅真实预算整理可重建 Responses 链。
- 不新增 LLM 汇编/翻译阶段。验证请求数、完整前缀、未缓存输入和总量，不承诺供应商实际命中率。
- 日志只保留有界原因、路径、ID/计数/版本等现有审计字段，不记录原始失败参数或凭据。

## 9. 故障矩阵

| 情况 | 必须行为 |
| --- | --- |
| 损坏 JSON/错误层级/缺必填 | 执行前拒绝，返回有界原因，不写业务对象 |
| 可选日期为空 | 省略，不编造日期；原对象不被原地修改 |
| 无版本观察/版本已变化 | 分别要求 get/报告冲突，不自动采用最新基线 |
| 一场未写完时取消/重开 | 保留暂存；原任务终态，显式续作补缺项 |
| 第一场已保存、第二场失败 | 第一场仍可见且 ID 不变，续作不重复创建 |
| 保存中事务失败 | 当前场整体回滚，既有场次与本批暂存保持一致 |
| 相同操作重试 | 返回相同 ID/进度，不重复创建或增加无变化版本 |
| 用户改动已保存内容/参考资料变化 | 保留手工内容；显式 CAS 修订，来源变化可见 |
| 额度结束 | 保留实际进度；checkpoint 为 partial，未处理错误仍 failed |
| 跨项目/会话/旧回调 | 拒绝，不读取或写入另一项目 |
| 旧分段/旧 IR | 沿用旧读取/幂等结果，不重复迁移用户正文 |

## 10. 验收

两协议下覆盖真实 Native/Pi/Worker/临时 SQLite 的分段、错误恢复、部分完成、取消重开与跨任务续作；包含 17 场 47 镜跨轮次保存且无重复。验证人物范围、共享属性继承、对白和动作不被重写、用户表单优先、最终消息前缀稳定。全仓门禁及生产 Worker 离线验证完成后才勾选实施；离线结果不作为真实模型叙事质量或缓存率证据。
