# 会话重复准备与交付验收修复计划

日期：2026-11-05。依据 [现场审计](./code-traces/2026-11-05-conversation-preparation-loop-audit.md)，先审计、后计划、再实施。

同日新任务暴露的剧本类型契约冲突与强制交接死锁另按[专项修复计划](./AGENT-CHECKPOINT-DEADLOCK-REPAIR-PLAN.md)修复；本计划原有通过项不能视为已经覆盖该组合路径。

## 范围与约束

- 同一任务内复用已加载工具、资源导航和已读取的工作证据；检查点不是业务进展。
- 依据相同证据识别重复准备，不设置任务总调用上限，不阻止不同镜头、版本或分页的正常读取。
- 由模型理解用户需求并登记执行交付项，Worker 只验证结构、授权与真实保存证据，不用关键词判断用户意图。讨论和查询无需登记制作计划。
- 交付项可以增加或细化，不能通过删除目标、降低数量或切换类型绕过验收。跨阶段保留交付项。无法完成时明确记录原因，以部分完成结束，不能冒充成功。
- 任务结果显示在对应回复旁；全局生成结束不等于资料保存。
- 不调用真实付费模型，不重放用户历史任务，不直接修改用户项目，不重启应用。全部测试使用临时数据及模拟供应商。
- 保持本地 SQLite、按需正文、草稿/正式标记、附件不自动入库及既有 CAS/权限边界。

## 顺序与验收

### R1：准备循环与交接

- [x] 增加重复导航、无效工具加载、交接后仍重复准备的回归；新版本/新分页/新目标和真实保存仍允许推进。
- [x] 检查点只接受新增成功证据；重复导航、失败调用、路由和交接自身不使其合法。
- [x] 工具加载明确返回新增项与复用项；跨交接保留当前导航及已取得的工作证据。
- [x] 定向测试通过并记录。

### R2：执行交付验收

- [x] 复用已有 checkpoint 工具和审计表登记交付项，不新增运行时存储服务或数据库迁移。
- [x] 结束时核验成功业务回执、真实文档类型、逐目标保存及镜头引用；没有开始写入也必须检出欠交付。
- [x] 支持明确的部分完成原因，保留全部欠交付项；交接不丢失计划。
- [x] 回归无写入、重复回执、缺一个镜头、错误文档类型、空绑定、计划降级、部分结束及完整 16 镜的离线验证。
- [x] 定向测试通过并记录。

### R3：对应消息的结果

- [x] 区分回复结束、保存操作完成、部分完成和停止；结果附于对应任务最后一段回复。
- [x] 后续只读回复不再给正在查看的旧任务显示全局“生成完成”。
- [x] 桌面定向回归通过并记录。

### R4：最终门禁

- [x] 运行项目 test、typecheck、lint、format:check、build，准确记录通过项和既有问题；只处理本修复引入的问题。
- [x] 更新本计划及检索计划交叉引用，说明未运行真实供应商及未修改历史项目的验证边界。
