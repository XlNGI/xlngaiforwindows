# 粗剪接点闪黑修复计划

2026-11-03。用户要求先设计计划，再按计划实施。此前审计证据保存在临时目录 `rough-cut-code-audit-20261103`；本轮基线备份在 `rough-cut-playback-repair-20261103`。

## 原因与范围

1. 可见 video 直接换源，尚未加载或定位到下一段入点就移除旧画面，可能露出播放器底色。
2. 低频 timeupdate 和固定 20ms 阈值导致边界误差；同源连续拆分会从已播放的 2.1 秒回退到 2.0 秒。
3. 过期 play promise 失败会暂停当前片段，缺少异步请求隔离。
4. 导出裁切后未归零视频 PTS：已复现 12 段预期 180 帧、实际 174 帧，部分接点间隔约 66ms，但旧时长校验通过。合成输出没有解码黑帧，不能据此断言用户现场黑帧属于导出问题。

保持硬切、单视频轨与同步原声；不增加淡入淡出或输入限制，不改源素材、真实项目数据库、Provider 或既有任务。保留其他未提交修改。本计划修复实现缺陷，不更改已确认产品需求，也不替代原粗剪 RC4 的发布验收。

## 实施顺序与验收

- [x] RP1 回归基线：新增预览交接与真实 FFmpeg 帧数/PTS 失败测试，保存红灯结果。
- [x] RP2 预览修复：独立双播放器控制，后台最多准备下一段，暂停且静音；元数据、入点 seek 和目标帧确认后才切换画面。使用有尺寸上限的画布发布已确认帧，加载期间保留上一画面，防止直接显示解码器在出点后的帧；只有当前播放器能出声。同源连续拆分不重新 seek；按视频帧回调检查边界，兼容无此 API 的浏览器；处理 ended 和序列终点。seek、暂停、编辑、换序列/项目、卸载隔离旧回调与 play 结果；有效错误向界面反馈。
- [x] RP3 导出修复：裁切后的 PTS 归零，30fps 帧数取整规则保留，明确尾帧补齐和精确音频长度；拼接以视频帧边界为准，避免 AAC 分段 padding 改变接点位置。输出增加帧数与时间戳验证，失败不发布成片，保留容量检查、取消及临时文件清理。
- [x] RP4 聚焦验收：慢加载保帧、快速 seek、连续同源片段、过期 promise、暂停/继续、终点/错误/卸载；真实随包 FFmpeg 覆盖 24/25/30/29.97fps、非帧对齐入点、短尾、静音/原声混合。逐帧验证数量、接点时间与合成颜色，无新增黑帧，不改源文件。
- [x] RP5 质量与交付：全仓测试、类型、lint、格式、构建、Rust 测试/格式与差异检查均已执行，实际结果及失败见下文；不将执行完成表述为全部门禁全绿。重建 Worker sidecar，检查当前进程实际加载状态，未手动重启。完成隔离真实浏览器媒体验证，保留 Windows WebView 真实项目复测边界。

## 设计约束

- 已有画面切换期间保持可见，不向下一段传播播放器低频事件造成的超出量；同源连续区间保留真实进度。
- 下一段未就绪时冻结旧画面并暂停旧音频，不跳过下一段开头，也不双路播放。
- 首次加载可显示加载状态；缺源或解码失败明确提示，不假装继续播放。
- jsdom 只证明状态、事件与调用顺序，真实 FFmpeg 验证解码输出；两者均不能单独证明 Windows WebView 实际像素显示。
- 发布画布按源比例缩放，最多 1280×720，适配现有预览尺寸；不改变导出分辨率。无视频帧回调 API 时，出点附近保留先前有效画面，可能提前约一源帧冻结，但音频和剪切时间仍按区间交接。

## 实施记录

- RP1：桌面 2 项新增测试均失败（旧源过早被替换、2.1s 回退到 2.0s）；真实随包 FFmpeg 12 段预期 180 帧、实际 174 帧。日志保存在本轮临时目录 `desktop-red.log` / `worker-red.log`。
- RP2：桌面工作台 9 项、独立播放控制器 13 项通过，粗剪目录共 32 项。覆盖元数据早于解码、帧回调早于 seeked、慢加载、连续拆分、媒体时钟落后于呈现帧、旧 play 拒绝、当前播放失败、快速 seek、暂停/继续、ended/重播、缺源、错误、清空和卸载。项目会话变化停止播放并复位，控制器按会话和序列重新创建。
- RP3：中间段使用 H.264/MOV 与精确长度 PCM，最终视频直接拼接、音频统一编码 AAC；避免每段 AAC 编码延迟。裁切后归零 PTS、30fps、尾帧克隆、精确帧数/音频采样数；每段与最终视频流式验证帧 PTS、帧时长、重复/缺失帧，校验通过才发布。
- FFmpeg 聚焦 22 项通过。12 段预期/实际均 180 帧，PTS 从 0 按 1/30 秒递增，红绿接点每 15 帧正确；24/25/30/29.97fps、[125,558)ms 与短尾 [1140,1200)ms 混合输出 60 帧、2000ms。解码颜色无黑帧，原声/静音 RMS 检查通过，源文件字节不变。
- 浏览器使用真实 RoughCutPreview 和临时 HTTP 服务、合成媒体，无项目 RPC。首先发现帧回调与 seeked 的顺序问题并修复；随后加入出点后黑色帧素材，发现兼容模式直接显示解码器越界画面的风险，改为仅发布确认帧。最终结果另记下文；该隔离测试不替代真实项目 Windows WebView 复测。
