2026-11-07，依据专项审计及用户批准的顺序实施。本轮只调整 Agent 职责，不按删除行数决定范围，不删除项目历史、完整结果或正式产物。

## 顺序与验收

1. [x] 文档创建与更新统一经过 Worker 业务执行身份、事务提交及真实回执；旧协议作为参数适配入口，不能拥有另一套防重规则。
2. [x] 验证新旧入口交叉重放、冲突、CAS、已有历史产物兼容；失败不得重复创建或丢失保存结果。
3. [x] Agent 初始上下文和每轮上下文由 ContextManager 统一组装；保留 ContextService 的预览、非 Agent 及显式业务用途。普通会话不自动注入资料正文。
4. [x] 取消旧 Native Agent 执行入口，旧准备协议改由 Pi 执行；保留普通原生 LLM 流式传输、研究及旧任务数据恢复。
5. [x] 删除无生产调用的 Router、恒定分支、旧提示词分类与仅维护其行为的测试；完成相关测试与仓库质量门禁，具体首轮失败及修正复测见下表。

## 兼容边界

- 不新增同职责的执行存储或上下文服务；复用 AgentExecutionStore、AgentDraftSubmissionService、AgentContextManager。
- 旧任务的 task artifact、目标、授权和版本继续读取；缺少稳定身份时仅绑定明确目标，不能按标题或正文猜测对象。
- 旧 RPC 保留参数与返回值兼容，运行时归属统一为 Pi。旧 native-agent 标记作为历史数据可读，不恢复第二套循环。
- 章节、改编提案、集结构等有独立业务约束的工具不能当作普通文档重复实现删除。
- 无破坏性数据库迁移，不回写历史审计。普通技术决策依据现有架构自主处理。
