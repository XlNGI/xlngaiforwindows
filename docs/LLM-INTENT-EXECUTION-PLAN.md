# LLM 语义判断与结构化执行

日期：2026-10-12
状态：实现、自动化验证、隔离验证及本地安装包构建完成；真实 Provider 与人工安装验收待验证

用户确认：提示词的语义由 LLM 判断。Desktop、Worker 不得用关键词或正则判断用户是否要求写入、拒绝否定句、拆分章节或提前返回 pending intent。

本决策覆盖统一 Agent、架构重写和小说计划中“Worker Intent Resolver 先解析普通提示词”的旧规则。

- 原始提示词先进入统一 Agent 的正常模型轮次，不增加独立分类请求。
- LLM 自行回答、澄清、检索或选择结构化工具。讨论、否定和目标拆解由模型理解。
- 工具可见性由当前项目、服务可用性、用户的结构化设置和预算决定，不由提示词关键词决定。
- Worker 校验结构化参数、项目/session/会话、真实目标 ID、CAS、锁、幂等、调用预算；保留费用、高风险操作与受保护 UI 的真实确认。
- 模型每次提交一个文档或章节草稿，Worker 事务化创建独立产物任务。多个章节由模型连续调用，分别拥有目标、版本和审核锁。
- 快捷按钮提供可选结构化目标提示，不在模型请求前创建章节或锁定写操作。
- 普通会话不自动注入小说、文档、记忆和约束正文，继续按需检索。本地 SQLite 是唯一运行时事实源。
