# 镜头页面与本镜参考图整理修复方案

日期：2026-11-16  
版本：1.0  
状态：布局与功能已实现；自动化、生产包验证和交付记录见第 8 节，真实安装包与 DOCX 版式验收单独保留。

## 1. 目标

镜头页面使用「视频提示词」「本镜参考图」两个主入口。将原「镜头衔接」中的素材选择、视频选帧、图片提示词及图片采用操作归入「本镜参考图」，让每个镜头都可以独立制作参考图。图片与视频正文分别保存、编辑及填表。

人物、场景、道具关系作为当前镜头的共享资料，只维护一处；图片用途及实际输入按生成阶段分别确定。分镜说明继续作为可选折叠区域。模型、参数、费用和实际生成沿用正常制作表单。

用户已确认本方案及补回目录后的布局。同步素材库优化方案及实施文档的 Markdown/DOCX，按本方案顺序实施；不提前改写已有阶段的完成状态。

## 2. 审计依据与问题

| 问题 | 当前证据 | 影响 |
| --- | --- | --- |
| 普通镜头共用一份正文 | `ShotInfo.prompt` 注释及 `ShotWorkspace.generate` 的 image/video 分支 | 静态瞬间和完整动态过程容易混用，图片入口可能收到视频正文 |
| 独立图片正文依附衔接记录 | `ShotContinuityBinding.imagePrompt`；`ShotContinuityPanel` 的编辑区位于 `binding` 条件内 | 首镜或没有选帧时，独立图片编辑入口不完整 |
| 同一工作流分散在多处 | 镜头正文、角色/场景参考、首帧、已生成图片与折叠衔接面板 | 图片制作与采用顺序不清楚，存在重复入口 |
| 模板作用域不直观 | 新会话从默认值初始化；Worker 按会话读取并冻结模板 | 用户可能以为先前会话的自定义模板已经沿用 |
| 用途由 Agent 声明 | `tools.load.workflow` 及 `promptTemplateKindForTools` | 页面已有明确操作目的时，仍可能选成另一类正文 |
| 参考说明仍有前端组装 | `ShotWorkspace.productionImageBindingPrompt`、`ProductionPanel.addProductionImageBindings` | 预览、Agent 与最终媒体参数需要保持统一输入顺序及用途 |
| 保存成功不等于语义合格 | 保存入口校验结构、真实 ID、类型、项目及 CAS；创作覆盖依赖 Agent | 正文写三人、绑定只有两人等遗漏仍可能落库 |

## 3. 页面信息架构

### 3.1 公共区域

- 保留「项目导航 → 场次与镜头目录 → 当前镜头编辑区」三栏。目录属于页面公共区域，不归入图片或视频页签；场次展开、镜头切换、当前项高亮、新建场次/镜头、勾选/全选、归档/删除及已归档/已删除入口均继续保留。
- 桌面默认显示目录，可以主动收起；窄窗口通过始终可见的「目录」按钮展开，不因响应式布局丢失目录入口。切换两个页签不改变目录位置、展开状态及当前镜头，切换镜头保留各自草稿。
- 镜头标题、所属场次、草稿状态。
- 两个主页签：视频提示词、本镜参考图。首次默认视频；用户切换后在当前镜头内保留选择和未保存草稿。
- 「资料绑定」只维护本镜角色、场景和道具关系，可折叠；参考图的更换不自动更改人物出镜范围。
- 「分镜说明」保持底部折叠。角色、场景原图可预览，并保留原有手动覆盖、默认值和不使用语义。

### 3.2 视频提示词

1. 本镜完整视频提示词：开场状态、人物动作、对白声音、机位运镜、自然估时及结束状态。
2. 本次视频选用图片：缩略图、顺序及普通参考/首帧用途；可跳转到本镜参考图调整，避免再维护一套绑定。
3. 主要操作：保存、Agent 编写、填充视频表单。填充不触发媒体生成。
4. 前后镜的动作阶段、朝向、速度和道具交接写入视频正文；图片仅提供可见状态，不承诺锁定全段连续性。

### 3.3 本镜参考图

按「参考来源 → 图片提示词 → 本镜图片」组织；宽面板可将图片结果放在编辑区右侧，窄面板按上述顺序纵向排列。

**参考来源**

- 角色、场景、道具默认图及当前镜头手动选图有清楚来源。
- 从当前项目选择图片/视频、从电脑显式导入、视频选帧沿用现有能力；上一镜视频只作快捷推荐。
- 视频来源、候选帧、确认帧保留真实时间点、哈希和基准选择。精确定位及批量抽帧按需展开。
- 没有额外来源也可以手写或请 Agent 编写图片提示词；只依赖项目文本时不声称已核对画面。

**图片提示词**

- 独立、可编辑的本镜静态正文，明确用途与选定瞬间。
- 创作目标可选构图参考、视频首帧或视频末帧；该选项描述创作意图，不自动改变实际视频输入角色。
- 仅写该瞬间能同时成立的人物、手部、道具、朝向、视线、机位、环境与光照。
- 主要操作：保存、Agent 编写、填充图片表单。图片提示词不以存在衔接来源为前置条件。

**本镜图片**

- 合并已有图片预览及原衔接结果选择入口，支持从项目添加、预览、排序、移除和用途选择。
- 生成结果先作为候选展示；用户明确采用后，才成为本镜视频输入。
- 沿用当前多张普通参考图、最多一张显式首帧规则。实际尾帧输入按当前模型和业务合同支持另行映射，不因创作目标选择“末帧”就宣称 API 已绑定尾帧。
- 移除本镜引用不删除原素材；不在镜头页另建素材库。

### 3.4 两组图片的边界

| 集合 | 用途 | 不自动执行的操作 |
| --- | --- | --- |
| 参考来源 | 帮助 Agent 理解画面、辅助生成本镜图片 | 不自动全部成为本镜视频输入，不自动成为首帧 |
| 已采用本镜图片 | 按选定顺序及用途填充视频表单 | 新生成结果不自动替换当前采用项，不自动增加付费任务 |

同一素材可以被用户明确用于两个阶段，底层按素材 ID 引用，不复制文件。普通角色参考、首帧等用途依实际生成阶段确定。

## 4. 数据与兼容方案

### 4.1 两份正文有各自的明确所有权

- 现有 `shots.prompt` 原文与版本保留，作为既有镜头正文的兼容入口；视频编辑和视频生产继续使用该正文。
- 为普通镜头增加独立的图片创作记录，建议项目 SQLite 侧表 `shot_image_prompts`：`shot_id`、`project_id`、`prompt`、`purpose`、`bindings_json`、来源版本、`row_version`、时间戳。最终字段名在合同阶段确定。
- 图片记录可以没有选帧来源；清空图片正文不删除选帧、已生成素材或视频正文。
- 图片与视频分别保有自身适用的引用集合；共享资料为候选来源，每次创作显式声明实际人物，避免把只出现在视频后半段的人物硬加进开场图片。
- 原 `shot_continuity` 保留来源选择、选帧、哈希及连续性证据；普通图片正文不再依附必须存在的衔接绑定。

### 4.2 旧数据迁移

1. 事务内复制已有 `ShotContinuityBinding.imagePrompt` 到独立图片记录，保存来源标识；保留旧原文用于兼容和核对，不再双向独立编辑。
2. 旧 `shots.prompt` 不按关键词分类、不批量改写，也不直接复制成两份“已确认”正文。
3. 对已经把静态描述写入旧镜头正文的记录，由 Agent 按用户目标审查并通过原有 CAS 原位修订；自动迁移只处理能够确定的存储关系。
4. 两处旧首帧/结果绑定归一到同一权威投影。已有用途、顺序、禁用及手动覆盖保留；冲突展示待核对，不静默丢弃。
5. 关闭重开、多窗口、只读旧项目、迁移失败回滚与备份恢复均需回归。

### 4.3 版本与失效

- 图片正文、视频正文、来源选择和已采用图片分别检查相应版本；跨项目/session、删除或缺失素材继续拒绝。
- 改图片文案不应无条件破坏视频引用；替换真实来源、画面目标或镜头状态会使相关创作依据待核对。
- 来源变化时保留旧正文及图片并显示待核对，阻止静默使用过期依赖；不因重新确认而清空可恢复的用户编辑。
- 只保留与本操作有关的迟到响应，切换镜头/项目不覆盖新目标或其他页签草稿。

## 5. Worker、Agent 与界面职责

### 5.1 创作阶段

1. 页面明确发起“编写图片提示词”或“编写视频提示词”时，提交明确用途及真实镜头定位；普通聊天继续由 Agent 理解语义，不用关键词硬分流。
2. 前端保存当前会话模板，提交用户原文与版本。Worker 按当前会话读取、校验并冻结通用及专项模板。
3. Worker 统一组装通用要求、当前用途模板和用户请求；所需镜头/项目正文与画面仍由 Agent 按需读取，不把整个项目自动注入普通会话。
4. Agent 编写对应正文，明确本产物实际人物/场景/道具引用，保存到对应图片或视频入口；两种正文互不覆盖。
5. 创作入口低调显示当前模板来源/版本，可查看或编辑。新会话默认模板与旧会话自定义模板不再让用户误以为相同；沿用旧模板需要明确选择，不自动继承历史约束。

### 5.2 预览与制作阶段

- Worker 提供统一的图片/视频填表预览投影，根据实际有序素材生成输入图片说明；前端展示相同投影，逐步移除页面各自追加说明的逻辑。
- 图片填表只读图片正文及本次生图来源，视频填表只读视频正文及明确采用图片；对应正文为空时提示需要编写，不拿另一份正文兜底。
- 用户在制作表单更改图片、顺序或用途后，用同一组装逻辑更新说明，并允许正常人工编辑；实际提交以用户确认的最终参数为准，不重新套入旧模板或旧绑定。
- 用户自定义/清空模板后，不在后台补入默认创作规则；模板正文用于指导创作，不机械附加到每份已保存成品提示词。

### 5.3 交付检查

- Agent 在保存/完成前核对适用要求与实际正文：图片/视频用途、完整正文、人物出镜与引用、视线站位、光照依据、时间与对白、负面约束及前后关系。
- Worker 检查真实 ID、类型、项目、版本、引用有效性、所选模型输入能力及有序输入；不按姓名字符串猜角色、不用正则冒充语义审查。
- 对 Agent 明确提交的实际出镜集合与绑定集合进行结构一致性校验；语义缺漏由 Agent 原位修正并读回。未完成内容审查时，不宣称“所有约束已通过”。
