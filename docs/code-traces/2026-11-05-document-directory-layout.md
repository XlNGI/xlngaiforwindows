# 项目文档目录布局优化

用户截图标出了角色与场景目录：窄面板的目录最高仅 160px，标题、生命周期与类型筛选占用大部分高度，长列表也会压缩内部行，正文与目录各自滚动时缺少清楚的边界。

- [x] 定位：确认 `App.tsx` 中的共享项目文档目录，以及 `styles.css` 的窄屏媒体查询和 `project-pane` 容器查询。
- [x] 实现：将固定的目录头部与独立滚动列表分开；窄面板将标题、新建入口和生命周期筛选放在同一行，类型筛选位于下一行。目录最大高度改为 `clamp(180px, 30vh, 272px)`，列表条目不再被纵向压缩。宽面板继续使用侧边目录。
- [x] 验证：相关 120 项测试全部通过；Desktop 类型检查、生产构建、App ESLint、变更源码格式和 diff 检查通过。
- [x] 浏览器：使用从实际 App 提取的目录 JSX、真实标题组件及角色场景编辑组件，配合内存示例数据验证 320 / 390 / 404 / 600 / 900px 面板，均无横向溢出；验证深浅主题、当前与归档切换、共享剧本目录，以及键盘滚动列表时正文保持原位置。

1440×900 视口、404px 面板下，目录头部为 66px，列表为 183px，可完整显示 3 项，正文区域仍有 484px；390×844 视口、320px 面板下，列表约 166px，正文区域约 410px。以上为隔离浏览器夹具的测量结果，不等同于 Windows Tauri 安装包验收。

本次只调整目录的前端结构和样式，没有更改素材库、检索、文档保存或归档规则，也没有修改项目数据库。素材库方案中的已确认产品要求没有变化，无需更改其 Markdown / DOCX 产品正文。
