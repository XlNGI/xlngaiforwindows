# 完整场次与逐镜头制作验证

日期：2026-10-17。

## 用户确认范围

场次按剧情逻辑组织，每个分镜表达清楚时间与画面；时长由动作、对白、反应、停顿和运镜推导。禁止为了凑满 15 秒或模型上限反向编排剧情。场次制作表单必须装入共享设定与全部镜头，并按用户所选模型自动填参数。

## 实现

- `packages/contracts/src/production.ts` 保留 v1，增加详细 v2：叙事目的、年代/季节/故事日期/日夜时段、地点天气布局、细分风格、人物外观服装表情视线道具与状态、相机与灯光、剧情预计时长及依据、首帧定格、转场和风格参考资源。
- 两条场次生成工具使用同一详细合同与解析校验；新提交必须包含 v2 场次和每镜 v2 指令。新场次必须有故事时段、地点与视觉风格；每镜必须有动作、景别和基于剧情的预计时长。保存的 v1/旧文本不做语义推断或固定时长回填。
- Schema v54 在项目 SQLite 增加 `production_change_set_instructions` 与 `production_defaults`。前者随变更集保存；批准时复用原事务和不可变制作指令记录。后者通过 CAS 维护项目视觉和视频输出默认值。
- `scene-production.ts` 继承共享设定、渲染全部分镜、累计时间轴并比较显式连续性事实。剧情预计时长与模型请求时长分开；离散模型规格可产生请求余量，预计剧情时长保持原值。
- 容量判断使用模型实际 JSON Schema，包括 anyOf 和离散时长。超限保留全部提示词，提供自然镜头分段。制作页可选择连续分镜段，按段预填并沿用原付费确认；不改变场次归属、镜头顺序或剧情。
- 制作范围记入 `ProductionSource.shotIds`，随原任务快照冻结。跨场次、乱序或不连续的制作段拒绝。分段继承前镜已声明的状态，整场仍可查看。
- 来源令牌包含全部子镜头及顺序、项目风格版本和明确参考资源状态。手动改过正文的旧结构会显示待更新，并保留当前正文供检查；不会拿旧估时直接提交。Agent 的按需读取只返回可编辑数据，不暴露内部校验令牌。
- v2 首帧生成只渲染选定静态画面，不把整段动作、对白或结束状态塞进一张图。千问图像合同的画幅/分辨率转为实际 size；超出像素范围显示冲突。

| 升级失败可重试且旧数据不变 | `production-migration.test.ts` 模拟 v54 迁移失败，确认版本仍 v53、无半建表，重试保留旧提示词 |
| 整场所有镜头进入表单 | Worker 验证 0—8、8—23 秒及共享时间/服装；Desktop 验证完整提示词和按段真实准备参数 |
| 不隐式提交多个付费任务 | 分段选择只编译本地表单；测试准备后拒绝确认，不调用真实 Provider |
| 来源修改后不能提交旧表单 | 覆盖分镜正文、增加/排序/删除、项目风格、资源及提交前令牌检查 |
| 不把旧文本猜成结构或固定秒数 | 兼容用例保留全部旧镜头文本，时间未知时仍未知 |
| 保留人工覆盖与异步隔离 | 原 Hook/ProductionPanel 回归；分段具有独立上下文键；旧目标迟到结果不写新目标 |
| 不扩大普通会话自动注入 | 仅按需生产工具返回内容；未修改普通会话正文注入和检索规则 |
