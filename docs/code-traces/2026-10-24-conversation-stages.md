# 会话按执行阶段展示

## 审计

- `ChatPanel` 原先将一条助手消息全文与整个任务的工具记录分开渲染，运行中和完成后的工具位置不同。
- Pi、原生 Agent 和桌面继续执行路径均将多轮可见文本累积到同一条消息；原有任务事件虽有稳定 sequence，但没有记录文本与工具之间的边界。
- 媒体审核队列位于消息滚动区域之外，表单不能按准备时间插入会话。

## 计划与实施

- [x] 在现有本地任务事件表中记录文本起始位置，每批工具之后首次出现文本时记录一次。不复制正文，不增加模型指令，不新建执行或存储系统。
- [x] 将阶段性文本、该阶段工具组及审核表单放入同一条时间线；工具返回摘要可展开，已完成阶段可折叠。表单状态在原位置更新。
- [x] 保留旧历史全文；缺少边界时不按文字内容猜阶段。支持同一时间戳的事件顺序，实时活动不重复显示旧工具。
- [x] 完成前后端回归、宽窄面板与深浅主题浏览器检查、类型/格式/构建检查并记录结果。

仅使用临时项目、模拟 Provider 与浏览器 fixture 验证，不操作真实项目或付费生成。

## 验证结果（2026-10-24）

- 桌面完整测试：64 个文件、575 项通过，包括阶段顺序、工具组折叠/展开、审核表单位置、会话切换与滚动跟随。
- Worker 相关回归：`agent-provider-loop-service`、`generation-service`、`pi-conversation-runtime`、`document-workflow-service` 共 194 项通过。临时 SQLite 实证验证文本边界去重、工具批次之间的边界与历史还原，事件不重复存储正文。
- Edge 浏览器：640/390 像素面板、深浅主题，共 17 次布局和顺序检查通过。覆盖工具返回展开、表单展开、重新加载、运行中至完成；无重叠、页面横向溢出或浏览器异常。截图与报告位于本地忽略目录 `apps/desktop/.m2-ui-conversation-timeline/`。
- 修复回归发现的问题：滚动容器保持稳定，切换会话仅重建审核队列状态；审核表单按钮在窄窗口下保持可见。
- `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`git diff --check` 通过；最终样式修正后再次完成桌面构建。构建仍提示现有主包体积较大。

新增阶段元数据适用于后续执行；旧消息缺少文本边界时保留原文，不推测拆分。未更改 Agent 提示词或工具执行策略，未替换已安装的桌面应用。

## 图二样式与实际事件回放复核

用户反馈运行界面仍像“整段回复加工具总表”。只读检查当前项目发现，最新任务已保存 4 个文本边界，`DocumentWorkflowService.getTask` 也正确返回这些边界；不能把问题直接归因于缺少后端记录。

- [x] 修复旧快照覆盖阶段记录的路径：会话任务缓存与当前任务合并时依据事件 sequence、任务 rowVersion、更新时间保留较新的快照，避免回退为完整正文与整块工具表。
- [x] 优先使用记录中的 messageId 关联助手消息与任务，支持历史分页未加载父用户消息的情况。
- [x] 阶段正文不重复显示“助手”标题，复制按钮在悬停或键盘聚焦时出现。运行中的工具组也默认收起，并移除吸附在滚动区底部的样式，工具记录与文字在原位置连续排列。
- [x] 桌面 64 个测试文件、579 项通过，包含过期快照、历史分页与运行中折叠回归；桌面类型检查与构建通过，Lint、格式与 diff 检查通过。
- [x] Edge 浏览器 18 次检查通过，含原有宽窄面板、深浅主题、展开与完成检查，以及当前项目最新真实事件的回放：4 段正文与 3 个工具组交替显示。

真实项目仅以 SQLite readonly 模式读取；回放截图与临时数据保存在本地忽略目录，未回写会话、绑定或生成任务，未调用付费 Provider。

## 初始轮询游标修正

会话从 `afterSequence: -1` 开始读取任务事件，底层事件服务也支持该值，但 RPC 校验此前只允许非负数，会在实际读取前拒绝初次轮询。现将边界校验最小值改为 -1，仍拒绝 -2；`agent-input-service.test.ts` 覆盖该回归，并验证从 -1 读取任务事件及还原问答表单。
