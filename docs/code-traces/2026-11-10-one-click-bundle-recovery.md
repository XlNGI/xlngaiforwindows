## 源码行为

- `production.bundle` 接入同任务、同工具、hash 校验的 prepared arguments。失败的 `put` 可用模型显式提供的 JSON pointer `set/remove` 修正候选字段，最多 32 项；不必重新发送整包。禁止越界数组、原型属性、修改包外字段，以及同时覆盖 `part` 或切换 operation。所有修正后仍执行原 Schema、授权、领域与版本检查；程序不推断或代填创作内容。
- 预校验（包括 prepared 引用解析错误）写入既有任务事件。无进展门禁合并这些事件与实际工具失败，按工具及具体错误原因区别字段；连续三次同类错误且没有候选修订或有效审查进展时，在下一供应商请求前停止。读取和重复 seal 不清除该历史。总 Token／时间／轮数预算保持原值。
- 候选领域错误带数组索引、localKey、声音 cue 索引与身份字段。Schema 提前表达 voice.sampleText、character／旁白与 visibility 的合法组合；画外角色不能靠改成旁白规避身份检查。
- 新增 `read_many`：显式指定 1–20 个候选 key 和 expectedRevision，总字符上限 10,000，并限制序列化 UTF-8 结果。返回实际 reads 与携带 hash／offset 的 remaining；只把交付的实际页面记作已读。任一项失效时不产生部分读回证据。单项 read 和旧版任务继续兼容。
- 第一阶段将 workflow 2 的 Skill revision 升为 9，说明局部修参、批量续读、制作提示词完整性、原始台词、自然时长及画外身份。全文语义仍由后续模型审查，程序不根据关键词填通过答案。
