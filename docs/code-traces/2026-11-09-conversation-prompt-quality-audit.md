## 2. 已确认的正文缺项

### C1：指定的视频正文组织方式没有落实到镜头

本轮要求原文：

> 正文按“输入图片说明 → 视频目标 → 【基础设定】→ 【氛围与画质】→ 动态流程 → 负面约束”组织。

12 镜均未出现 `【基础设定】` 或 `【氛围与画质】`，实际为连续剧情／镜头描述段落。已确认的缺项是用户指定组织方式未落实，不代表段落中完全没有环境或摄影信息；不能以关键词缺失推断整体语义为零。

当前第一阶段没有实际参考图，“没有输入图片时省略图片说明”仍适用，不能为补分区捏造输入图片。此格式要求来自本轮用户要求，不应硬编码成所有会话的通用创作 Schema。

### C2：相对时间只存在于 beats，没有写入生成正文

本轮要求原文：

> 动态流程：按本段相对时间从 0 秒写至自然内容结束，每个动作节拍明确起止秒数。

12 镜均有 `timing.estimatedDurationSeconds` 和 `beats`，但其实际 `prompt` 均没有数字秒数，未把指定的相对时间节拍写入正文。例如第一镜时长 8 秒，beats 为 0–5 秒动作和 5–8 秒停顿，正文只有“写完停笔”“短暂思索”，没有这两段相对时间。

`prompt` 与对应 IR.prompt 在全部 12 镜中逐字一致，说明当前缺项已经存在于模型提交并保存的创作正文，不是提示词列与 IR 投影不一致导致。`packages/generation-adapters/src/production.ts` 的 `compileProductionParameters` 只消费传入正文及显式参数，不把 beats 自动渲染成创作文字；应用不应新增语义拼写逻辑来掩盖漏写。

### C6：把对白清单的格式规则扩大成正文禁令

截图对应的发言及持久记录中，模型称 Skill 要求“台词原句独立呈现且不带引号／叙述包装”，并针对 1-3 镜头做最小格式修订。

实际读取的声明是：

> 在场次/镜头交付项 requiredTexts 中逐句登记……逐字项只复制源稿中的原句，不自行拼入说话者标签、引号或格式；说话者、语气与顺序在读回时另外核验。

这里限制的是 `requiredTexts` 中登记的逐字检查项，不是禁止实际提示词使用说话者、引号或叙述。模型把检查清单的格式要求误扩展为正文禁令，并将注意力集中在这一修订上，C1/C2 仍未解决。

专项应验证“要求适用字段与对象”的边界，防止把校验机制要求变成新的创作约束。是否需要改写具体对白仍应按源稿与用户正文要求判断，不能仅由精确匹配清单的写法推导。

## 4. 对专项计划的影响

目前可以确认的问题链是：**要求有持久原文 → 生成正文没有完整落实 → 结构化时间不等于正文时间 → 模型审查仍提出通过 → Worker 因协议／就绪原因阻止通过**。尚不能把原因统一归为 IR 不合理、模型能力不足或前端截断。

本实例需要纳入以下强制验收：

1. 按本轮实际要求核对每镜正文，不只看结构字段或对白命中。
2. 整场与单镜分别验收，避免摘要占用完整整场生成正文；场次与镜头时长按相同范围核对。
3. 明确 `requiredTexts` 清单、提示词正文、音频计划和媒体输入的适用规则。
4. 审查证据注明来自正文还是辅助结构；“正文必须包含”不能用 beats／data 证据代替。
5. 当前 reviewId 与依赖版本变化可定位，未就绪明确返回真实缺项，避免反复提交空 passed。
6. 从原始用户要求独立评价最终内容，不以“12 个目标全读过”或“83 次模型请求”代替质量证明。

实施顺序和完成门禁统一见[整个会话专项优化计划](../AGENT-CONVERSATION-QUALITY-AND-EFFICIENCY-PLAN.md)。
