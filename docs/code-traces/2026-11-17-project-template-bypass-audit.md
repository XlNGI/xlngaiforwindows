## 代码中的原因

1. [agent-context-manager.ts](../../apps/worker/src/agent-context-manager.ts) 的普通 `prepare` 从恢复状态的 `workflow` 或 Runtime 用途中选一个用途；`general` 对应空的专项列表。模型声明的通用用途能一直覆盖后续图片文档创作，没有按本次制作任务及真实输出用途检查一致性。
2. [prompt-templates.ts](../../packages/contracts/src/prompt-templates.ts) 的 `promptTemplateKindForTools` 优先接受显式 workflow；通用 `document.submit_draft` 无法仅凭工具名区分角色图片、场景图片、道具图片或普通文档。因此不能靠加载保存工具就保证选对模板。
3. [agent-tool-definitions.ts](../../apps/worker/src/agent-tool-definitions.ts) 同时提供统一 `prompt.generation.request` 与可加载的通用 `document.submit_draft`。后者可直接创建制作资料，本次执行没有受到统一生成入口的约束。
4. [agent-policy-instructions.ts](../../apps/worker/src/agent-policy-instructions.ts) 仍指导角色逐个走 `document.submit_draft`、通过 `tools.load.workflow` 获取专项、整包走旧 `production.bundle` 用途操作。它与新任务的一次完整生成合同并存，给模型保留了互相竞争的执行路径。
5. [prompt-generation-service.ts](../../apps/worker/src/prompt-generation-service.ts) 的现有校验负责用途、结构、引用、版本、事务和回读；即使正确进入统一生成器，这些检查也不能证明正文语义逐项覆盖模板。现有统一实施计划明确保留了这一区别。

当前运行的是本仓库 debug Desktop，子进程为 `node dist/index.js`；Runtime 已包含统一生成入口，相关 dist 文件更新时间为 15:41:21。因此不能把本次简单解释成“机器只运行了没有新入口的旧安装版本”。

## 修复建议及顺序（尚未实施）

### 1. 先保证模板必达，收敛制作入口

- 按 Agent 的结构化任务声明区分“新建制作提示词”“已有提示词 CAS 编辑”“普通文档/小说设定”。不以用户文本关键词路由，也不把所有 character 文档都强制视为角色生图。
- 新建制作提示词由统一请求声明来源版本、全部用途和交付目标，使用既有统一生成器。修正工具说明和系统指令，不再同时要求新任务使用旧的用途切换编排。
- 普通文档和已有内容编辑保留其业务工具，但制作提示词写入必须校验任务用途和本次已投影模板的身份一致。声明 general 后提交角色图应在写入前被拦截，保留候选、补入对应冻结模板后重新创作；不能拿已经生成的旧正文重新提交就算补齐。
- 混合产物按每个对象用途绑定模板。不能为了“同时做角色、场景、道具”选 general，也不能把三份图片模板全部用于同一个视频正文。
- 覆盖本次“生成资料并绑定已有四镜”的完整合同：已有场镜 ID、版本和绑定目标需要进入明确的任务目标；不得创建重复场镜，或在新资料保存后就结束而漏掉绑定。生成正文一次完成与随后本地关系解析、CAS 保存可以分开；不能要求模型再写一次正文。

### 2. 保证用户修改后的文本成为新任务依据

复用已存在的保存与快照机制：提交前保存编辑稿，通过整体 CAS 取得版本；冻结通用与对应专项全文、用途和 hash。新任务用新版本，执行中修改只影响之后任务，原任务恢复仍使用其冻结版本。若明确要求正在执行的任务采用新模板，应显式重新冻结/启动新一轮，不能悄悄替换旧任务合同。

空模板保持为空。修改为单幅立绘后，不从旧默认模板、Skill、历史记录或保存工具重新加回五视图。模板只是普通可编辑文本；程序保证选择、全文传输与版本身份，不解析成固定创作字段。

### 3. 将结构成功与内容符合分开验收

结构、真实引用、版本、事务和独立回读继续由程序校验。正文覆盖则以本次冻结模板及本轮明确修改为依据，核对每个适用要求在最终正文中的具体证据；若增加模型语义复核，它是新的内容验收步骤，不能把现有结构检查换个名字称为已实现。

这类复核应动态读取当前模板，不能写死五视图、六角度或固定标题正则。问题应指向具体对象和要求；有界修复后仍未满足，保留可编辑候选并标明待核对及未满足项，不无限重试，不声称已全部合格。只有真正阻塞的冲突或模型容量问题才需要集中澄清。

任意自然语言模板都无法得到绝对语义保证；可确定保证的是使用正确版本、正确用途、完整文本、真实保存及不把未验收内容伪报为通过。

### 4. 以修改模板的回归矩阵验收

- 默认设定板、改成单幅立绘、任意改写版式、清空模板、通用与专项的本轮明确修正。
- 普通 Agent、多用途混合请求、一键入口、已有文档 CAS 编辑、生成资料并绑定已有镜头。
- 执行中改模板、重启恢复、多窗口 CAS 冲突；旧任务使用原快照，新任务使用新快照。
- general 下创建制作提示词必须被拦截；普通讨论和小说人物设定仍能正常完成；空模板不作为缺失错误。
- 结构错误、模板语义遗漏和真实供应商失败分别验证，保留候选和准确状态，不伪造通过，不自动启动媒体生成。
