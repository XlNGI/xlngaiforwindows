# 镜头提示词填充与绑定声明

## 用户目标

左侧镜头中已经绑定的图片和语义关系应一起填入右侧生产表单。两处提示词都用带图片缩略图的内联标签展示输入；提交给模型的提示词明确说明每张图片对应的角色、场景或帧用途。

## 审计

- 镜头工作区已经从结构化镜头／场次绑定和有效镜头角色范围解析输入图片；填表回调将素材 ID 和用途传给应用层，应用层按绑定文档标题或素材别名生成有序表单快照。
- 生产面板已将角色、场景绑定写入普通 `prompt` 或结构化 `content[].text` 的输入图片说明段，并根据最终模型图片顺序生成引用编号。请求准备阶段使用相同参数生成实际请求。
- 左侧镜头提示词已使用共用内联图片编辑器，但此前仅能投影正文中明确存在的图片编号，没有把当前绑定图片及其角色／场景关系投影到提示词。
- 当前共用编辑器只持久化普通文本。新增的左侧绑定说明应继续作为动态投影；实际镜头正文、草稿和数据库记录不因打开页面而被自动改写。
- 图片与角色、场景的关系有现有结构化来源。普通提示词中的姓名、地点或占位文字不建立素材绑定。

## 设计

1. 使用镜头解析出的有效有序图片选择构造提示词声明；角色和场景名称来自绑定文档，首帧和连续性图片保留各自用途。
2. 左侧编辑器把声明段与可编辑正文一起显示，并将声明中的编号映射为当前素材身份对应的缩略图标签。编辑时从回传文本移除自动生成段，只保存用户正文。
3. 点击填表时传递同一组图片选择和经过身份重映射的正文。右侧表单继续在选择模型后按模型输入顺序投影编号和声明，最终提交沿用现有参数快照。
4. 不扩展 IR、数据库或资产同步机制；不改动 Agent 检索和会话模板；不发起生成请求。

## 实施顺序

1. 完成镜头页绑定声明投影和正文回写边界。
2. 增加镜头编辑器与真实请求聚焦回归，覆盖标签、角色／场景关系、输入顺序及不按姓名推断。
3. 运行聚焦测试和全仓质量门禁，记录实际结果。
4. 同步素材库优化方案及实施计划的 DOCX 版本，检查文档结构并尝试渲染页面。

## 实施与验证结果

- 镜头编辑器按当前有效的有序图片绑定投影缩略图标签、编号和角色／场景／首帧／连续性声明；用户编辑时自动生成的声明从回传正文剥离，避免页面打开或保存正文时改写绑定语义。
- 填表提交与显示使用同一组图片身份和顺序。生产面板与最终请求按模型输入顺序生成绑定声明，明确说明图像用途及结构化角色／场景关系；未从普通提示词中的姓名推断绑定。
- 桌面聚焦回归 81 项及场景绑定回归通过；全仓 `pnpm test` 通过 1,005 项测试。`pnpm typecheck`、`pnpm build`、本次变更源码 ESLint 和 `git diff --check` 通过。
- 全仓 `pnpm lint` 仍被未修改文件中的 4 个既有错误阻塞：`apps/desktop/src/font-scale.tsx`、`apps/worker/src/change-set-service.ts`、`apps/worker/src/content-service.ts`。`pnpm format:check` 仍报告未修改的 `apps/worker/src/change-set-service.ts`、`apps/worker/src/content-service.ts`、`apps/worker/src/production-service.ts` 和 `apps/worker/src/request-validation.ts`。
- 未修改真实项目数据库，未发起付费生成。
- DOCX 页面渲染：两份同步后的 DOCX 均已使用随附 `render_docx.py` 尝试渲染；两次均因 Windows 环境缺少 LibreOffice `soffice.exe` 而未生成页面 PNG，DOCX 版式视觉验收待可用渲染器时完成。

## 2026-10-27 用户反馈复核

- 生产表单切换能力时保留调用方明确请求的能力；即使当前适配器目录或连接没有兼容模型，也显示该能力下的无兼容模型状态，不再静默退回旧的视频表单。
- 镜头填充在读取绑定期间显示进度并禁用重复点击，避免异步解析看起来像按钮无响应。
- 每次显式填充都会清除相同生产上下文中的旧表单覆盖，并将左侧当前提示词和图片重新应用；制作内容编译覆盖参数时重新投影绑定声明，保持右侧可见提示词与最终请求中的角色、场景关系一致。
- 回归覆盖右侧面板已打开后重复填充、缺少目标能力适配器、绑定解析延迟，以及编译结果返回原始镜头提示词的情形。用户无需重新打开项目；当前项目状态会沿组件属性更新。
- `pnpm --filter @ai-video/desktop test -- App.test.tsx ProductionPanel.test.tsx ProductionPanel.scene-bindings.test.tsx ShotWorkspace.test.tsx` 通过 184 项；桌面 `typecheck`、构建、涉及文件 ESLint 和 `git diff --check` 通过。构建提示单个 JS chunk 超过 500 KiB。未发起媒体生成。

## 2026-10-27 Wan 音频提示复核

- 审计确认：Wan 3.0／Prime 当前修订 3 的 Schema 均接受 `reference_audio`。万相官方 Binding 的音频传输为 `upload`，UniComp Binding 为 `url-only`；`isOfficialVoiceVideo` 判断的是本地声音可否上传，不代表模型是否接受参考音频。
- 原表单在 UniComp 隐藏场次声音选择，又在提交时因场次存在本地声音绑定而统一报“当前连接不支持声音输入”，使用户既看不到具体限制，也无法只在当前表单取消声音。
- 修复后，对于接受参考音频但未接入本地上传的连接，显示本地声音选择和渠道限制说明。提交校验依据当前表单选中的声音，不因用户已取消的场次绑定继续拦截；取消只作用于当前表单，场次数据不变。
- 用户取消本次本地声音后，可以保留手动填写的公网参考音频和对应提示词进入任务准备。尚未进入实际输入的本地声音不会生成音频绑定声明。官方连接原有的本地样本、固定声音版本、绑定声明和费用确认链路继续有效。
- 未增加 UniComp 本地上传协议，不自动切换供应商、上传文件或提交生成；本次是生产表单的能力说明和选择修复，不改变素材库产品规则、检索或项目存储。
- 验证：Desktop 表单／声音输入聚焦 80 项、Worker 准备／运行时／合同聚焦 34 项通过；Desktop `typecheck`、生产构建、本次修改源码 ESLint／Prettier 和 `git diff --check` 通过。构建仍提示单个 JS chunk 超过 500 KiB。测试使用隔离夹具，未调用付费供应商，也未修改真实项目数据库。
