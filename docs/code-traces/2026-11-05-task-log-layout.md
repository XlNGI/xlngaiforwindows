# 任务日志面板布局优化

用户截图标出了与素材库并排的任务日志面板。原列表使用固定 92px 类型列、标题列和带英文状态码的状态列；“加载更多”是横向内容容器的直接子节点，进一步占用了列表宽度，打开详情后还可能成为两列网格的第三项。详情的适配依赖整个窗口的媒体查询，无法适应宽窗口中的窄面板。

- [x] 实现：日志页使用独立紧凑工具栏，显示已加载条数、刷新和两项筛选；任务卡片分开显示类型、中文状态、最多两行的标题和时间；“加载更多”移入列表底部，与任务共用一个滚动区域。
- [x] 详情：以任务日志容器的实际宽度为依据，760px 及以下使用整页详情和“返回列表”，宽面板使用两列；详情标题可换行，支持 Escape 返回，关闭后恢复到原任务按钮的键盘焦点和列表位置。
- [x] 空态：区分首次读取、读取失败、无任务与筛选无匹配。
- [x] 测试：TaskLogView 14 项、FileTaskList 1 项全部通过，覆盖详情读取、未知提交状态、等待执行名额、分页、筛选、刷新、关闭/返回/Escape 和焦点恢复；分页测试确认入口属于列表。
- [x] 静态检查：Desktop 类型检查、生产构建、变更 TSX 的 ESLint、变更源码 Prettier 检查通过。构建仍提示主包超过 500KB。
- [x] 浏览器：隔离夹具直接使用实际 TaskLogView 和共享样式，使用内存 RPC 示例数据验证 280 / 320 / 390 / 460 / 600 / 760 / 900 / 1100px 面板，无横向溢出；检查了深浅主题、1.5 倍字号、窄面板详情与返回焦点、宽面板详情分栏、51 条分页和筛选无匹配提示。

460px 面板、1280×720 验证视口下，工具栏高 103px，列表可用高度 515px。截图存于本地忽略目录 `.m2-ui-task-log/task-log-after.png`。这些是隔离浏览器夹具的验证结果，不等同于 Windows Tauri 安装包验收。

本次仅调整任务日志前端布局与展示，没有更改素材库行为、项目检索、任务存储或本地优先架构；相关方案的已确认产品要求没有变化。
