# 镜头提示词组织与内容一致性

日期：2026-10-20。

## 用户确认

用户反馈自动提示词存在人物断臂侧别矛盾、动作缺少视障特征、对白归属含糊、起止状态混排、重复字段及非本镜人物参考图。确认改进创作指令和自动组装，事实无法确定时只提示待核实；用户最终表单仍可自由编辑，不恢复剧情事实提交阻断。

## 实施顺序

- [x] C1 文本组织：静态描述精确去重，站位与初始/结束状态分开，分段动作保留时间和说话人；对白、动作与音效中的有意重复保持。保留“无补光”“无运镜”等明确否定，修正重复“避免”前缀。
- [x] C2 创作与提醒：Native/Pi 共用工具说明要求按需核对人物资料、屏幕空间、动作节拍和原始对白；增加可选 reviewNotes，作为本地提醒而非画面要求。已明确角色 ID 的断臂侧别疑点、视障行走细节不足和对白边界不清给出非阻断提醒，保留原始设定。
- [x] C3 参考范围：单镜/分镜段自动参考按声明的角色 ID 筛选，场次卡片及整场制作保留共享角色；用户显式选图和首帧保留。旧数据角色声明未知或指令过期时沿用继承，不从普通提示词猜角色。
- [x] C4 全仓自动检查与方案内容同步：全仓 1,690 项测试及类型、静态、格式、构建检查通过；素材方案 Markdown 与 DOCX 的对应需求段落已同步。DOCX 视觉渲染受环境限制，单独保留待验项。

## 设计与边界

`production-prompt.ts` 只整理结构化字段，不能理解所有自然语言矛盾。侧别检查仅对已明确绑定角色的少量断臂表达给出疑点提示；不按姓名建立关系，不把文字差异当作确定冲突，不替用户选择左右。更复杂冲突由创作 Agent 在同次编排中核对并写入 reviewNotes；没有额外自动 LLM 调用。

视障动作由创作指导要求具体化，不由代码给所有盲人套用固定步态，不自动添加跛行或擅自决定伤腿。原有指令可以重新编译得到清晰排版，但代码不会自动补写旧稿缺少的动作、台词或人物事实，也不批量修改已保存用户文本。

reviewNotes 不进入供应商提示词。制作页把内容提醒与模型适配说明区分显示，内容提醒自动展开。保存草稿、Agent 按需读取、整场/单镜编译均返回有界提醒；提醒不成为新的提交拒绝条件，实际参数、素材归属和费用确认仍保留。

本地项目 SQLite、素材文件、检索索引及普通会话正文注入规则不变；GitHub 仅管理源码与文档。素材方案的自动参考范围规则由用户本轮明确更新，Markdown 与 DOCX 同步。
