## 审计结论

只读检查当前实际项目的 SQLite，使用 `better-sqlite3` 的 `readonly` 与 `fileMustExist`，未调用项目打开服务、迁移或写入。

“屋外雨坪”文档（`28e988d4-5b1c-49b7-b30e-ce0dedefcf1e`）实际类型为 `scene`，项目没有 `prop` 文档。目录筛选却允许当前文档绕过类型条件，导致切到“道具”后仍显示正在编辑的场景。修复该筛选分支即可，无需改写项目文档类型。

顾清影（`bd3ff42f-5541-4daa-a300-eed6dc000fe0`）已有角色图且已绑定到场一。镜头 1-2（`8d43f5c8-8dd4-4387-af6c-cacc0c39354a`）正文在收尾写她出现在二楼栏边，但其 IR 的 `references.characterDocumentIds` 只包含独眼头目和黑衣杀手组。表单沿结构化范围解析参考图，因此没有带入顾清影。此例属于 Agent 的语义声明遗漏。

## 实施内容

- 目录严格按工作区与类型筛选，正在编辑的文档也不例外；切换筛选不丢失编辑器草稿。
- 工具 schema 与共用 IR 声明说明角色、场景、道具的语义；不需要道具时可为空，不创建占位道具。
- 单镜角色引用声明覆盖背景、远景、无台词及收尾短暂入画人物；仅提及或画外存在的人物不因此成为图片引用。Agent 根据语义保持正文与 IR 引用一致。
- 默认会话模板同步表达上述要求，已保存的用户会话模板保持原内容。
- Worker 沿用现有结构、项目、文档 ID、类型、授权、CAS 与幂等保护；不增加正文姓名匹配、自动补人物或另一套绑定逻辑。

明确空数组表示无角色；新镜头省略时继承场次，修改省略时保留已有范围。人工选图、禁用和最终审核表单继续按既有规则处理。已审核的 Agent 表单仍直接提交，不退回成待提交草稿。
