# 会话内问答表单

## 审计

用户要求选项和问题也用表单呈现，并延续会话中正文、工具组、表单按时间排列的交互。现有媒体审核表单处理图片、视频与音频参数，没有通用问答声明或持久化答案，不能借用媒体生成提交逻辑承载普通问题。

语义问题由 Agent 自主决定，通过工具 JSON 声明；系统负责验证、保存、展示及幂等，不解析 Markdown 猜测问题，不增加固定创作流程。

## 计划与实现

- [x] 声明核心工具 `conversation.ask`：稳定 key、标题、说明，以及 1–8 个单选、多选或文字问题。所有问题可直接填写其他答案或补充，选项无默认勾选。
- [x] 复用项目 SQLite 的 `agent_task_events`，保存 `agent.user_input.requested` 与 `agent.user_input.answered`，不增加表或迁移。同任务同 key 声明幂等，修改同 key 的问题被拒绝；同表单重复提交相同答案返回原结果，修改已提交答案被拒绝。
- [x] 增加项目会话作用域内的 `agent.input.get` / `agent.input.submit`。校验必填、选项身份、单选数量、重复答案、字符串及载荷边界；答案与问题定义一起读取并持久化。任务快照和增量事件读取均返回可渲染表单。
- [x] 时间线在完整工具组之后、下一段回复之前显示问答卡片。已回答状态在原位置更新，重新加载还原答案摘要；没有文本边界的旧历史也可显示表单。
- [x] 提交后复用原会话 `sendMessage` → `agent.run` → 原执行器，键为 `question-answer:<formId>`。保存答案后启动失败可继续处理；保留用户未发送的正文和附件，不向新选中的项目发送旧表单答案。
- [x] 分离窗口复用同一表单与主窗口执行入口，增加请求确认回执；主窗口明确拒绝切换后的会话，错误返回表单并允许重试。
- [x] 最终回归、类型、Lint、格式与构建检查。

## 验证记录

仅使用临时项目、模拟 Provider 与浏览器 fixture；不改真实项目，不调用付费 Provider。

- 临时 SQLite 验证：问题与答案恢复、请求/提交幂等、语义和 schema 校验、项目/任务/会话范围、普通生成幂等键关联。
- 授权工具循环实证：`conversation.ask` 初始可用，调用返回表单回执，经原任务事件读取还原；无需额外授权确认。
- 桌面交互验证：单选、多选、自定义答案、必填校验、重复点击、启动失败重试、旧快照、只读、刷新恢复。App 集成测试证明使用普通 `agent.run` 且保留草稿与附件。分离窗口覆盖主窗口接受与拒绝两种回执。
- Edge 浏览器：640/390 像素、深浅主题，待回答/已回答/刷新恢复共 12 项顺序与布局检查，无页面溢出、重叠或浏览器异常；截图与报告位于忽略目录 `apps/desktop/.m2-ui-agent-questions/`。
- 修正既有阶段回放测试的时间排序不稳定性：用生成返回的 assistantMessage ID 核对保存正文，避免用户和助手同毫秒创建时依赖末项顺序。
- 完整桌面测试：65 个文件、588 项通过。Worker 相关回归：8 个文件、271 项通过，覆盖原生成、工具网关、Provider 循环、Pi、任务读取与 RPC 处理。Lint 修正后再次运行桌面相关 106 项测试通过。
- `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`git diff --check` 通过。构建仍提示已有主包体积较大。

## 边界

新问答由 Agent 调用声明工具后显示，既有 Markdown 提问不自动转换。表单工具保存问题后返回回执，不阻塞 Agent 执行线程；用户提交答案后作为普通用户消息继续任务。尚未选定可用文字模型时保留答案，选择模型后可继续处理。

## 补充：结尾的下一步选择

复现中，Agent 保存章节并输出内容概览后，用普通文字询问“继续下一章或审阅/调整本章”。该轮任务的工具清单包含 `conversation.ask`，但没有调用记录或 `agent.user_input.requested` 事件，因此前端没有表单可显示。该轮发生在 Worker 重启后，不能归因于旧进程尚未加载工具。

保留现有实现，仅补充同一工具声明和会话输入指导的适用范围：Agent 决定询问的可选后续方向也通过 `conversation.ask` 声明，即使当前任务已完成，或只有一句包含多个方向的话。完成情况和内容概览继续作为普通总结；无需用户选择时正常结束，不强制每次完成后创建表单。表单创建后不在普通回复中再列一套相同问题或选项，也不把回执当作用户答案继续执行。

新增回归使用真实 Pi 执行器、临时 SQLite 和模拟 Provider，分别覆盖 Responses / Chat Completions 的“保存章节 → 创建下一步表单 → 结束回复”过程。逐轮检查表单工具和指导仍可用，恢复任务后只有一份章节草稿、一张待回答表单，内容概览保留，且未生成下一章或伪造用户回答。同时验证工具刷新不会重复追加输入指导。模拟 Provider 用来验证调用链和恢复能力，不能证明真实模型一定自主调用表单工具。

本次验证：Worker 的指导、Provider 循环、Pi 运行时及表单服务共 4 个文件、175 项测试通过；全仓类型检查、Worker 构建、修改文件的 ESLint / Prettier 与 `git diff --check` 通过。当前桌面 Worker 仍为构建前启动的 stdio 进程，应用重启后新回复使用更新规则；未强杀进程或重写既有聊天内容。

## 2026-10-25 审核暂停语义

问答表单创建后，Provider 当前轮立即结束，任务和阶段持久化为 `waiting_review`，不会继续创建下一 Provider step，也不会再次报告不存在的 open step。用户提交答案仍通过稳定幂等键复用普通 Agent continuation。Worker 相关回归与全仓门禁已通过。
