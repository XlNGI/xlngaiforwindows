# 角色页按提示词设计新音色

用户先要求音色提示词位于对应角色提示词页，再指出缺少生成按钮，并明确需要按提示词设计新音色。

## 实现

- 角色页“音色提示词”区增加“生成音色”。打开时先保存当前角色与音色的待保存编辑；失败保留输入。点击后打开独立生产表单，自动带入当前角色、已保存的描述和试音文本，可选择已测试的 MiniMax 官方连接及后续配音模型。角色页保留提示词编辑及入口，不再内嵌提交表单；选择其他制作类型、关闭生产面板或切换来源时清除音色设计上下文。
- 新增 `characterVoiceDesign.prepare/confirm`，冻结真实角色、音色文档及其版本；准备阶段不调用供应商，确认阶段再次检查版本、连接、只读状态和并发角色锁。确认凭据五分钟过期且仅用一次，超出 500 字符的试音文本拒绝提交，不截断。
- Native 使用固定 `https://api.minimax.cn/v1/voice_design`、Bearer 凭据和官方 `prompt`／`preview_text` 字段，读取真实 `voice_id`／`trial_audio`。不把既有 TTS 当作音色设计，不生成占位音色 ID。后续配音模型不发送到设计接口。
- 复用既有受控路径、取消、容量限制、MP3 检查和 FFmpeg 完整解码，将音频存入项目 `assets/audio/reference`。事务内同时保存音色版本和声音参考版本；绑定冲突回滚文件移动并保留缓存 MP3 与音色 ID 清单，以便核对已产生的结果。
- 成功后显示音色 ID 和受控音频预览，并通知声音参考与制作来源刷新。角色／项目切换丢弃迟到的界面结果和费用批准。已提交远端请求不能保证撤销或退款，系统不自动重试付费请求。
- 修复供应商失败只显示通用英文错误的问题：提取 `base_resp.status_code`，按已知错误码解释鉴权、余额、限流或参数问题，并显示经过脱敏和限长处理的 `status_msg`；兼容非 2xx HTTP 响应内的业务错误。凭据、URL、响应正文和试听十六进制不进入诊断提示。
- 失败时在原项目 `cache/dubbing/*.mp3.error.json` 保存时间、操作编号、来源 ID、错误码与状态；不保存提示词、密钥、供应商正文或原始错误说明，记录失败不覆盖原错误。原先失败未保留供应商码，不能回溯断言其根因。
- 将 `characterVoiceDesign.confirm` 加入后台调度，生成过程中仍可读取、编辑或关闭项目；通过实际生成音频夹具验证万相、Seedance、MiniMax 的官方视频输入能读取同一角色声音参考，未触发第二次供应商调用。
- 无数据库迁移，无素材库或检索规则变更；保留工作区已有的其他修改。

## 验证

- Desktop 全量：93 个文件、838 项通过；包含独立生产表单、普通音频制作／角色生图切换回归及新音色面板的费用确认、取消、只读、超长输入、关闭后迟到批准、重复点击保护与供应商失败显示。
- Worker 音频服务 30 项、音频请求验证 69 项、后台请求调度 9 项，共 108 项通过；使用真实 SQLite 和随包 FFmpeg 生成的媒体夹具、模拟供应商返回。覆盖新音色保存、重开、原子绑定、确认前版本变化、冲突恢复、取消后保留已知结果、拒绝无效音色 ID、失败诊断和视频声音参考复用。
- Worker handler、Native bridge 与音频边界：180 项通过（其中 69 项音频边界与上一组重合）。
- Worker 配音 RPC 集成与其余请求验证：33 项通过。
- Rust `cargo test dubbing_provider --no-default-features`：15 项通过，包括描述／试音长度、来源字段、响应合同、HTTP 拒绝及供应商错误码／说明脱敏。
- 根目录 `pnpm build` 通过（contracts 至 Worker、Desktop 完整生产构建）；变更文件 ESLint、Prettier、Rust 格式与 `git diff --check` 通过。Vite 仍提示既有主包超过 500 kB，未阻止构建。

验证只证明源码和本地工程行为。未调用真实付费音色设计，未替换当前用户安装实例；真实音质与安装后交互仍待验收。

接口依据：[MiniMax 音色设计文档](https://platform.minimaxi.com/docs/api-reference/voice-design-design.md)，2026-11-10 核对。
