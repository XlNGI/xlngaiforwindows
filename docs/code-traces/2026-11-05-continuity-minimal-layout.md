# 镜头衔接界面精简

用户要求优化截图中的镜头衔接区，并明确“极简，将功能表达清楚就行，减少文字”。本次仅调整前端排版与文案，沿用已确认的多来源、人工基准、原尺寸图片、数量限制、CAS 和填表流程。

- [x] 审计：已读素材库两份方案、镜头衔接多来源与改词重新确认计划；定位重复视频选择、纵向视频卡片、320px 播放器及三层边框造成的空间占用。
- [x] 实现：移除重复说明与嵌套边框；已选视频改为紧凑行，名称用于切换预览，叉号移除，省略长文件名；取消重复视频下拉。视频采用完整 contain 显示，高度为 `clamp(160px, 24vh, 220px)`。时间、前后微调与添加画面集中一行；批量帧数、范围与抽帧集中下一行。缩短 Agent、提示词与填表按钮文案，保留完整无障碍名称和必要错误反馈。
- [x] 自动化：Desktop 衔接来源、衔接面板、项目素材选择及镜头填表共 **51 项测试通过**；Desktop 类型检查、生产构建、变更代码 ESLint、Prettier 和 diff 检查通过。既有测试改用稳定的无障碍按钮名称，继续验证多图填表、只读、基准确认、批量取消和图片用途。
- [x] 浏览器：隔离夹具使用真实面板、内存示例数据和本地生成的 H.264 横竖视频；320 / 390 / 576 / 900px 容器内均无横向溢出，选帧控件全部位于容器内。实际加载 180×320 和 480×270 视频，720px 高视口中播放器约 173px。验证视频切换、两个视频各 4 帧产生 8 个候选、多选与指定基准后确认、浅色 320px 布局和精简按钮保存／填表回调。
- [x] 来源入口布局修正：用户补充截图指出两个入口被推到左右两端。移除项目选择器的 flex 撑宽，让“从项目素材选择”和“选择电脑文件”共用紧凑操作栏，展开内容在下方独占整行。重跑上述 51 项测试、Desktop 生产构建（含类型检查）、变更代码 ESLint、Prettier 及 diff 检查均通过。浏览器实测 320 / 390 / 576 / 900px 容器中按钮均相邻同排、间距 8px，展开列表与选择器等宽且无横向溢出；浅色 320px 和确认后仅图片选择器也通过检查。

浏览器抽帧接口使用模拟数据，实际视频仅用于播放与版式检查；不将该结果作为真实项目 FFmpeg 或 Windows Tauri 安装包端到端验收。未修改用户项目或发起媒体生成请求。预览截图为合成素材。

本次是显示层精简，没有变更素材库及镜头衔接的功能要求，产品 Markdown / DOCX 正文不需变更；多来源计划 M4 中既有全仓静态门禁、DOCX 版式及 Windows 实机验收仍未完成。
