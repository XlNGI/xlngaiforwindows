# 会话检索重试与进度停留修复

日期：2026-10-16。用户报告：修改小说设定时，会话长时间显示“正在调用工具”；追问后出现两条运行进度。

## 只读核查

读取当前项目 SQLite 中的生成、工具审计和任务事件。第一轮约运行 4 分 1 秒，第二轮在第一轮结束前启动，约运行 2 分 8 秒；两轮最终均完成。三份文档由第一轮保存为待审核修订，第二轮遭遇的两次 revision 冲突来自第一轮的并行写入，不能解释为“被拒绝的写入实际上成功”。核查未修改用户项目。

第一轮连续四次检索使用 `sourceTypes=["document"]`，均为空；目标实际上是 `novel-reference`。随后三次读取使用了文档 ID，均返回 `LIBRARY_HANDLE_INVALID`。检索服务可用，第二轮不限定来源类型的结构查询和真实句柄读取成功。

存在小说资料绑定但尚无 `novel_profiles` 的项目中，`project.get_context` 的结构来源曾把这些对象标成 `document`，与资料目录、检索索引和 `resourceMap` 不一致。另外，底层检索与 Agent 授权的次数上限是 4/8，与已确认计划的 8/16 不一致；工具成功结果也未提供提示词所说的剩余预算。

## 不变量与修复

| 不变量 | 实现与验证 |
| --- | --- |
| 同一项目、同一会话最多有一轮活动生成 | 在创建消息、上下文快照及生成记录的同一事务内查询 `prepared/streaming`；重复幂等键仍复用原生成，不同会话可独立运行。跨调用者、原生及旧生成入口均有测试。 |
| 拦截第二轮不得停止第一轮或创建输入残留 | 返回中文 `CONFLICT`，`retryable=false`；完成或取消后允许下一轮，恢复中断仍走既有逻辑。测试核对消息、快照及生成记录数不变、无新 Provider 调用。 |
| 目录中的来源类型与索引一致 | 尚未建立小说 profile 时，已有活动小说绑定也返回 `novel-reference`；不读取文档正文。 |
| 空检索与服务失败有区别 | 保留精确类型筛选；空结果提供纠正提示，建议按真实 sourceType 查询或省略筛选。不得静默扩大用户指定的范围。 |
| 读取仍需本任务真实句柄 | 无效句柄错误明确说明文档 ID、版本 ID 和 resourceId 不能代替句柄；不增加直接按任意 ID 读取的旁路。 |
| 按需召回和预算边界保持明确 | 按既有计划统一为最多 8 次 search、16 次 read；Agent 总工具预算和文档调用预留仍生效。成功工具结果返回实际剩余预算；审计仍不保存正文或原始句柄。 |
| 界面状态跟随原始对象和终态 | 已恢复的运行任务阻止发送第二条请求；保留输入。交错回复按 `replyToMessageId` 绑定原任务；已完成生成不再被延迟任务快照显示为运行中。未同步的调用结果不冒充成功。 |
| 等待模型与工具执行可区分 | 工具执行时显示“正在调用工具”，工具完成后等待后续模型输出显示“等待助手回复”；保持停止生成入口。 |
| 恢复观察持续跟踪主任务 | 重新进入会话时，先选择 queued/running 的主任务，再选择 waiting_review 草稿任务；较新的草稿不抢占主任务轮询。App 回归覆盖完成后恢复发送且保留输入。 |

提示词同步解释 `novel-reference`、当前版本正文读取及句柄规则。没有新增关键词业务路由，没有自动注入全文，没有修改素材库或付费提交规则。
