# 小说目录布局修复

用户截图标出小说工作区的目录，并确认问题是目录太挤、滚动或显示不完整。窄面板原先将整个目录限制为 160px，搜索与选择工具和列表共用滚动容器，资料分组和章节容易被截断。

- [x] 定位：确认 `NovelWorkspace.tsx` 的目录结构，以及 `styles.css` 中 `project-pane` 容器宽度不超过 600px 时的高度限制。
- [x] 实现：搜索和章节选择工具固定在列表外，空间足够时排成一行，窄面板自动换行。资料、分卷和章节放入独立且支持键盘滚动的目录区域；条目保持正常高度，不被纵向压缩。窄面板目录最大高度改为 `clamp(180px, 30vh, 272px)`，内容少时按实际内容收缩，正文与目录之间增加边界。
- [x] 功能验证：小说工作区、目录标题和 Markdown 编辑器相关 33 项测试通过。
- [x] 页面验证：使用真实 `NovelWorkspace`、编辑器和样式，配合内存示例数据，在 Edge 浏览器验证 320 / 390 / 500 / 600 / 900px 面板、600 / 844 / 900px 视口高度、深浅主题、1.6 倍字体、分卷、搜索、全选、空列表和单章节。
- [x] 滚动验证：所有长列表场景中，键盘 End 都能到达并完整显示最后一章，Home 能回到顶部；目录工具区和正文保持原位置，没有横向溢出。单章节和一项大纲在 500px 常规面板、320px 短窗口中均不需要目录滚动。
- [x] 质量检查：Desktop 生产构建（含 TypeScript 检查）、变更组件 ESLint、变更文件 Prettier 和 diff 检查通过。

900px 高视口、500px 面板下，目录工具区为 30px，列表为 219px，可同时完整显示大纲和 4 章，正文区域为 430px。320px 面板、600px 高视口中，工具区自动换成两行，目录最多 180px，正文仍有 182px。以上为隔离浏览器夹具测量结果，未验收 Windows Tauri 安装包。

浏览器截图、测量数据和验证脚本保存在本地忽略目录 `.m2-ui-novel-directory/`。本次调整目录前端结构和样式，沿用现有的搜索、选择、标题编辑、保存与归档行为。
