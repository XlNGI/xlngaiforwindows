## 3. 补修范围

- 制作阶段检查与普通交付义务一起返回。当前读回、内容修复和语义验收优先；未到阶段的资料生成与最终绑定标明前提，最终数量、逐字项、引用与目标义务仍全部保留。普通会话不增加制作流程。
- 已读回的部分场次仍有未保存清单时，明确继续同一清单；不要求对不完整范围提交尚未就绪的整阶段验收。完整范围的逐字项与结构检查缺陷继续阻止首阶段通过，复用原分配结果，不把尚未生成的后续对白塞进已保存镜头。
- 整场全文投影缺陷继续阻止对应整场或整体完成；已有证据的镜头仍可独立审查，避免把整场缺陷扩大成所有镜头均不能验收。逐字要求变更进入审查身份，不复用旧通过。
- 错误提示给出准确的 `put_scene` 参数层级，说明校验拒绝没有改变 stage/version，避免无依据宣称接口变更或重复加载/开始。
- 复用现有不可变 Result Store 修参。仅对 staging 允许显式删除三个不被根 schema 接受的错放字段；仅对已存 `put_scene` 允许显式设置 `scene.title`。其余嵌套路径、正文、ID 与版本不开放此修正接口；原授权、最终 schema、项目/任务/工具、hash 与 CAS 校验继续执行。原候选不变，无自动搬字段、无自动补写正文。
- 制作表单测试等待已选择声音实际反映到音频说明，再保存快照；图片输入测试等待真实提交按钮可用后点击。只修正测试同步，没有修改媒体生产逻辑。
