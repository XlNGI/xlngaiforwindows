# 场次与镜头补齐草稿生命周期

用户补充：所有草稿目录都需要批量操作，场次与镜头也应提供归档和删除。此前的草稿批量删除只覆盖文档与小说目录，遗漏了独立存储的场次／镜头；此前“所有目录已覆盖”的结论需以本补修为准。

本次“同步”按上下文指与其他草稿目录保持相同操作能力，不增加远程数据同步。“删除”继续使用可恢复归档；不清除正文、IR、人物／场景／素材绑定或发布历史，不归档共用资料文档。项目与索引继续存储在本地 SQLite，正文按需检索、草稿／正式标记与附件入库规则不变。

按以下顺序完成：

- [x] 存储与协议：Schema v74 为场次与镜头增加独立归档时间，不复用镜头制作状态；新增带目标类型、行版本与归档／恢复动作的 Worker 接口。事务内检查项目、只读状态、CAS 与已发布分镜，写入生命周期审计；升级失败整体回滚，可重复重试。
- [x] 父子与只读边界：归档场次通过父级状态隐藏镜头，保留镜头自身归档状态；恢复场次不会恢复单独归档的镜头。禁止在归档场次下创建镜头，拦截已归档结构和关联分镜正文写入。新建条目的排序位置包含已归档行，恢复不会产生排序冲突。
- [x] 目录与检索：默认场次／镜头列表、文档目录、项目资源目录、检索导航、正文搜索与资料目录排除已归档结构及关联分镜；显式归档检索仍可读取保留的索引。兼容迁移期间尚无新列的旧检索结构。
- [x] 界面：场次和镜头均可勾选、全选、取消选择、归档或删除；父子同时选择时只提交父级归档，确认框说明子镜头处理和未保存修改。部分失败保留失败项，成功项即时隐藏；项目作用域变化后停止剩余批次。提供“已归档 / 已删除”及逐项恢复入口，归档当前场次／镜头后清理相应编辑器。
- [x] 定向回归：真实 SQLite 验证内容／IR／绑定／排序、父子独立状态、已发布保护、CAS、项目边界、只读权限和默认检索；IPC 注册和归档恢复往返；v73 升级回滚及重试；组件批量失败与作用域切换；App 中脏镜头编辑器关闭与恢复已保存内容。首次新建分镜后刷新镜头行版本，验证紧接着归档使用最新 CAS，不产生过期版本错误。
- [x] 最终门禁结果汇总：已执行并记录通过项及范围外失败，详见下方；不将全仓门禁标为全部通过。
