# 会话要求约束模板

用户确认：提供会话级要求模板，用户可以在发送前修改，发送时将最新模板与本次请求一起提交。

## 行为与入口

- 在会话输入框上方展开“本会话要求约束”。没有保存记录的会话提供一份可编辑的分镜制作模板，包含故事时间、地点、天气、视觉风格、角色与场景连续性、场次编排、逐镜明细、完整场次视频提示词及表单参数要求。
- 用户可以直接编辑、载入初始模板、清空或单独保存。清空后保存／发送不会再次自动补回模板。未保存编辑在当前窗口切换会话后保留。
- 发送前先等待该会话模板加载，保存当前编辑，再提交“本会话要求约束 + 用户本次请求 + 当前附件说明”。空模板保持原始请求。模型选择和参数补充继续使用原始请求重新组合，避免模板或附件重复。
- 普通助理请求和其他工作只遵循本次任务相关条款，模板不强制用户生成场次。项目文档、章节、记忆及项目生产约束仍按需检索；本功能只显式附加用户可见、可编辑的会话要求。
- 约束保存失败或发生版本冲突时保留消息及编辑，不发起生成。界面提供冲突说明和重新加载入口。主窗口、独立会话窗口共用同一模板状态。

## 持久化与实现

- 项目 Schema v55：`conversation_prompt_templates`，会话与项目外键、跨项目触发器、20,000 字符上限及 `row_version` 乐观锁。会话删除时级联删除，数据留在本项目 SQLite。
- RPC：`conversation.promptTemplate.get/save`，注册于实际 IPC 方法白名单，严格校验参数。只读项目和归档会话不允许保存。
- `use-conversation-prompt-template.ts` 按项目、Worker 会话期和会话 ID 隔离编辑及异步请求。旧会话加载／保存回调不能覆盖当前会话；同时触发保存与发送会合并同一保存操作。
- Agent、旧版 LLM 和离线消息保存均使用同一组合规则。完整提交内容保存在原用户消息中，重试复用该次请求。
