## 根因和修复范围

1. 普通任务的 `workingData` 只接受用户请求命中 ID／完整标题、约束或已登记目标的资料。泛化请求即使实际读过剧本、角色和场景，也无法跨历史整理保留。改为保留**本任务实际显式读取、仍活动且通过当前版本校验**的资料页；大于 6,000 字符的已读页也保留实际正文。未读文档和其他任务正文不会进入工作集。整包制作原有独立源稿／候选机制保持。
2. 64K 是旧过程整理目标。移除借此驱逐唯一工作资料的分支，避免历史仍声称 `selected_source_included`、实际工作资料却已被删。真实模型容量和输出余量检查继续生效；容量确实不足时明确失败，不能依靠循环重新读取。
3. 原始请求与会话约束的正文依旧仅投影一次，同时保留需求 ID、来源、哈希和正文位置；计划可以引用真实 `original`，不会因文本去重丢失合同身份。持久化完整原文不变。
4. Registry、Pi 预检／冻结、Worker 执行及授权轮转共同按操作识别不可变 `checkpoint operation=result`。同一响应允许最多八次结果读取，完成后统一刷新授权；`state/read` 涉及状态整理或旧检查点合同，继续串行，其他写操作与 `tools.load` 也继续独立执行。参数验证、作用域和每步配额仍执行。

不提高或关闭四次空转阈值，不把“多条可追溯父任务”当作本次终止原因。该保护在现场检测到真实的无保存循环；修复的是促成循环的上下文和工具链缺陷。
