# 外部请求限流与熔断

日期：2026-09-22。状态：代码及自动化验证完成；真实 Provider 和安装包验证未执行。

## 边界与不变量

- Native 进程内所有 LLM 流、Provider JSON/二进制请求、公开研究请求共用网络准入控制。按规范化服务 origin（协议、主机、端口）隔离；同一地址的不同模型和凭据共享配额。状态不含密钥、正文或完整 URL，不进入项目 SQLite。
- 全局和单服务同时限制在途请求、请求速率、突发额度和等待数量。流式请求直到完成/失败/取消才释放名额。排队有期限并响应已有取消信号；取消和本地拒绝不计供应商故障。
- 单服务连续瞬时故障触发熔断。冷却后只有一个真实业务请求可探测；成功关闭，失败重新打开。旧的在途请求不能关闭后来打开的熔断器。
- HTTP 429 遵守有界 Retry-After 冷却，不作为服务故障累计；网络/超时/408/5xx 计失败，认证和参数错误不触发故障累计。
- 熔断与限流不新增自动重放。现有视频轮询的每次重试都重新经过准入。媒体请求未发出的拒绝与已发送但结果未知严格区分；后者仍为 submission_unknown，禁止自动重提。
- 本地 Native 入口另设有界执行名额，防止尚未进入网络队列就创建无限线程。取消控制消息不排在业务请求之后。
- Native 进程共享保护覆盖各窗口/会话。Worker 图片/视频远程下载、开发用公共 DNS 查询、旧 TypeScript LLM transport 共用 Worker 进程内等价保护；重定向逐跳准入。Native 与 Worker 两个进程、多个独立应用实例之间不共享额度，因此“全局”指各自进程内上限。
- 调度与超时使用单调时钟；仅解析 Retry-After HTTP 日期时使用墙钟。每进程最多保留 256 个服务状态，仅安全淘汰已恢复且没有在途/排队的服务，不通过换地址重置保护。
- 本地存储、参数序列化和回调异常不计远端失败；远端错误正文不能伪装成本地未发送错误。查询失败与下载失败保留原有已提交事实。

## 默认策略

全局在途上限 8、每服务 3；全局每秒 4 次（突发 8）、每服务每秒 2 次（突发 3）；全局排队 32、每服务排队 8、最长排队 10 秒。连续 5 次瞬时失败（60 秒窗口内）熔断 30 秒，半开探测并发 1。Retry-After 最长 30 分钟，缺失时冷却 30 秒。配置集中在调度器内，以便通过测试调整，不增加第二套凭据配置。

Native 业务线程入口上限 48。研究桥另保留 16 个连接读取名额，成功接入业务执行后转移名额并持有到响应写完；本地取消不经过业务队列。提前取消记录最多 256 个、60 秒过期，活跃取消记录最多 48 个且不淘汰，避免取消风暴造成无界内存增长。

## 状态与故障矩阵

| 状态/事件 | 行为 |
|---|---|
| 额度足够 | 获取许可后发送，终态释放 |
| 并发/速率不足 | 有界等待，按服务内顺序调度，其他服务仍可前进 |
| 队列满/等待超时 | 明确拒绝，未发送请求，不记远端故障 |
| 排队取消 | 退出队列，未发送，不消耗有效并发 |
| 网络/408/5xx | 记失败；到阈值打开熔断器 |
| 429 | 设置服务冷却，后续请求快速拒绝 |
| Open 冷却结束 | Half-open，仅放行一条现有业务请求 |
| 探测成功/失败 | Closed / 重新 Open |
| 已发送媒体请求断线 | 保留 submission_unknown，不自动重放 |
| 应用退出/重启 | 内存调度状态消失；持久化任务沿用原恢复语义，不重提付费任务 |

错误通过现有传输契约返回；新增 REQUEST_NOT_SENT 表示本地准入拒绝、网络请求尚未发出。界面展示明确的中文繁忙/冷却提示，不将排队视作已提交。
